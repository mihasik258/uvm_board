# Платформенный слой OCV: ALINX VD100 (Versal xcve2302)

Слой отвечает только за плату. Он даёт окружению PS с Linux, такт, сброс и одно окно AXI4-Lite.
Ядро платформы, генератор, прогонщик и модели не меняются: окружение, которое прошло
косимуляцию, собирается под плату той же командой с теми же аргументами.

```
PS (A72, PetaLinux) ── M_AXI_LPD ── SmartConnect ── AXI4-Lite ──► ocv_hub ─┬─ source ─► DUT
      │                                                                    ├─ sink   ◄─ DUT
   NoC ── DDR4 (память Linux)            clk_wizard ── такт окружения ─────┘  monitor ◄─ DUT
```

| Что | Где | Значение |
|---|---|---|
| окно хаба | физический адрес PS | `0x80000000`, размер `2^addr_w` (не меньше 4 КиБ) |
| такт окружения и DUT | `clk_wizard` от генератора 200 МГц платы | `OCV_CLK_MHZ`, по умолчанию 100 |
| сброс | `pl0_resetn` CIPS → `proc_sys_reset` | сброс DUT дополнительно — регистр `DUT_CTRL` хаба |
| заморозка DUT (`lossless`) | `BUFGCE` (`OCV_USE_BUFGCE`, `OCV_BUFGCE_SIM_DEVICE=VERSAL_AI_EDGE`) | задаёт сборка, генерированная обёртка не меняется |
| PS | конфигурация CIPS из эталона ALINX | загружается штатный PetaLinux с SD-карты |

## Состав

| Файл | Что |
|---|---|
| `build.sh` | сборка: обёртка → программа для PS (статический aarch64) → Vivado → `BOOT.BIN` |
| `tcl/create_bd.tcl` | блок-дизайн платы: CIPS, NoC/DDR4, такт, сброс, мост на хаб |
| `tcl/build.tcl` | проект Vivado, синтез, реализация, PDI, отчёты |
| `tcl/ps_config.tcl` | конфигурация PS из эталонного дизайна ALINX (данные платы) |
| `rtl/ocv_vd100_top.sv` | верхний модуль: BD + окружение, выбранное при сборке (`OCV_ENV`, `OCV_AW`) |
| `constrs/vd100.xdc` | выводы DDR4 и тактового генератора |
| `tcl/bridge.tcl` | ячейка моста PS → хаб (SmartConnect); общая для платы и для симуляции моста |
| `tools/make_bootbin.sh` | `BOOT.BIN` = наш PDI + прошивка A72 (bl31, u-boot) из рабочего `BOOT.BIN` |
| `tools/ila_capture.tcl` | съём ILA отладочной сборки (`OCV_DEBUG=1`) по JTAG платы в CSV и VCD |
| `../../sw/board/ocv_busbench.c` | цена обращений PS к окну хаба по видам доступа (сборка: см. «Профиль») |
| `sim/run_bridge_sim.sh` | мост PS → хаб без платы: настоящий SmartConnect + окружение + программа PS через DPI |

## Сборка

```bash
export VIVADO_SETTINGS=<Vivado 2023.2>/settings64.sh
export REF_BOOTBIN=<рабочий BOOT.BIN платы>      # источник bl31/u-boot
export LINUX_DIR=<каталог с image.ub и boot.scr> # Linux с SD-карты, без изменений

# любое ядро: те же аргументы, что у sim/cosim.sh
platforms/vd100/build.sh examples/mac16/mac16.json examples/mac16/mac16_model.c \
                             examples/mac16/mac16.sv

# SCR1: обёртка над тем же скриптом (исходники ядра, дефайны, тестовые программы)
examples/scr1/build_vd100.sh
```

`OCV_STOP=sw` пересобирает только программу для PS (секунды), `OCV_STOP=bd` только проверяет
блок-дизайн (около минуты), `OCV_STOP=synth` останавливается после синтеза. `OCV_DEBUG=1` —
отладочная сборка с ILA (ниже), по умолчанию в каталог `build/vd100/<имя>_debug/`. Результат — в `build/vd100/<имя>/` рядом с описанием:

| Путь | Что |
|---|---|
| `sdcard/` | `BOOT.BIN`, `image.ub`, `boot.scr` и каталог `ocv/` — всё это копируется на раздел FAT SD-карты |
| `sdcard/ocv/` | `ocv_<имя>` (прогонщик + модель), `run.sh` (адрес и размер окна уже подставлены), тестовые файлы |
| `reports/` | `util.rpt`, `timing.rpt`, `summary.txt` (такт, WNS/WHS, ресурсы окружения и DUT) |

## Запуск на плате

После загрузки с SD-карты (консоль root):

```sh
mount /dev/mmcblk1p1 /mnt        # раздел FAT карты (при другом номере — mmcblk0p1)
/mnt/ocv/run.sh --info           # сначала: мост, такт, прошивка — ничего не запуская
/mnt/ocv/run.sh --batches 8 --throttle-out 128
```

Параметры `run.sh` — параметры прогонщика, как в косимуляции. Перед прогоном программа сверяет
хаб: идентификатор платформы, `DUT_ID` (CRC32 описания), раскладку каналов и геометрию буферов.
Прошивка от другого описания не будет прогоняться с чужой моделью.

`--info` читает каталог хаба и все слоты напрямую и сверяет каждое значение с метаданными, не
останавливаясь на первом расхождении. Он также проверяет, что счётчик тактов идёт и что запись
доходит: регистр `THROTTLE` каждой точки, первая и последняя запись буфера каждого источника.
Всё, что пишет, возвращает на место. Итог — строка `INFO: hub, endpoints and bus OK` или
`INFO: PROBLEMS FOUND` с перечнем.

| Что показал `--info` | Где искать |
|---|---|
| `no OCV hub at this address` | не тот `BOOT.BIN` на карте или неверный `--base` |
| `DUT_ID` не совпадает | прошивка и программа от разных версий описания |
| `CYCLES ... STOPPED` | нет такта PL или окружение держится в сбросе (`pl0_resetn`) |
| запись/чтение `FAILED` | мост PS → хаб: отладочная сборка и ILA |
| программа зависла на первом чтении | шина не отвечает: отладочная сборка и ILA, триггер `ar` |

### Отладочная сборка (ILA)

`OCV_DEBUG=1 platforms/vd100/build.sh ...` — то же окружение плюс ILA на шине AXI4-Lite хаба
(адреса, данные, handshake, ответы, сброс; 4096 отсчётов). На Versal ILA нельзя поставить ячейкой
BD, поэтому он вставляется в синтезированный нетлист, а отладочный хаб Vivado добавляет сам.
JTAG платы подключается к компьютеру, образ грузится с карты как обычно:

```bash
vivado -mode batch -source platforms/vd100/tools/ila_capture.tcl \
       -tclargs build/vd100/<имя>_debug/ocv_vd100.ltx bus.csv ar
# на плате, после строки "armed": /mnt/ocv/run.sh --info
```

Триггер: `ar` — первое чтение хаба, `aw` — первая запись, `now` — сразу (проверка самого ILA).
Результат — `bus.csv` и `bus.vcd`.

## Мост без платы

```bash
platforms/vd100/sim/run_bridge_sim.sh examples/mac16/mac16.json examples/mac16/mac16_model.c \
    examples/mac16/mac16.sv -- --batches 2 --throttle-out 128
```

В xsim стоит та же ячейка SmartConnect, что на плате (`tcl/bridge.tcl`), с портом в форме
`M_AXI_LPD` (AXI4, 128 бит данных, 44 бита адреса, ID 16), за ней — сгенерированное окружение.
Ведущий AXI4 обращается к шине так, как A72 через `mmap`: одиночные 32-битные передачи, данные и
строб в полосе адреса `[3:2]`, со случайными задержками (`BRIDGE_JITTER`, по умолчанию 30 %).
Программа PS — та же, что на плате (прогонщик и модель), подключена через DPI-C.

Результаты для mac16: `--info` проходит; полный прогон — 2 пачки, 2048 записей, 6744 чтения и
4109 записей шины, ни одной ошибки ответа, `PASS`. Мутация ведущего (данные всегда из полосы 0)
даёт `FAIL` на первых же регистрах — стенд различает правильный и неправильный мост.

C-часть собирается системным gcc в разделяемую библиотеку: встроенный в Vivado 2023.2 компоновщик
(binutils 2.37) не компонуется с glibc этой системы (`.relr.dyn`).

## Замер: косимуляция против платы

Набор прогонов каждого ядра задан один раз (`examples/<ядро>/bench.txt`); сборка кладёт его и
`bench_board.sh` рядом с программой на карте. Время — собственное время прогона, которое печатает
прогонщик: стимулы, DUT, сливы, модель, сверка, без сборки и загрузки.

```bash
tools/bench.py host examples/scr1 -o scr1_host.txt   # косимуляция (Verilator)
# на плате:  /mnt/ocv/bench_board.sh > /mnt/ocv/board.txt
tools/bench.py table scr1_host.txt board.txt             # таблица Markdown с ускорением
```

Результаты (косимуляция — Verilator на этом компьютере; плата — VD100, A72 под Linux, PL 100/80 МГц;
время — собственное время прогона):

| DUT | Прогон | Записей сверено | Косимуляция, с | Плата, с | Ускорение | Итог |
|---|---|---|---|---|---|---|
| mac16 | 64 пачки | 131 072 | 0.196 | 0.196 | 1.0× | PASS / PASS |
| mac16 | 64 пачки, паузы | 131 072 | 0.210 | 0.197 | 1.1× | PASS / PASS |
| SCR1 | `hello` | 9 610 | 0.143 | 0.052 | 2.8× | PASS / PASS |
| SCR1 | dhrystone (40 сливов) | 164 891 | 0.829 | 0.565 | 1.5× | PASS / PASS |
| SCR1 | случайная, seed 1 | 35 936 | 0.334 | 0.142 | 2.4× | PASS / PASS |

На плате время прогона целиком определяется стороной PS (обмен с хабом по одному слову через
`mmap`, модель, сверка): за время прогона mac16 хаб насчитал 19.5 млн тактов = 0.195 с при 100 МГц,
то есть ПЛИС почти всё время ждёт. Одно обращение PS к хабу — около 100 нс (10 тактов между двумя
соседними чтениями `CYCLES`).

Если карту не хочется вынимать, файлы можно передать через консоль:
`fpga/alinx_ve2302/scr1/tools/rvfi_ship.py --dest /tmp <файлы>`.

## Результаты сборки (Vivado 2023.2, после трассировки)

| Окружение | Такт | WNS / WHS, нс | Окружение целиком: LUT / FF / BRAM / DSP | из них DUT | Платформа (хаб + каналы) |
|---|---|---|---|---|---|
| mac16 (3 канала по 1024) | 100 МГц | +5.702 / +0.013 | 430 / 403 / 5 / 2 | 17 / 35 / 0 / 2 | 413 / 368 / 5 / 0 |
| SCR1 (программа 16384 + `lossless` монитор 4096) | 80 МГц | +0.198 / +0.007 | 12511 / 7253 / 77 / 3 | 11951 / 6874 / 33 / 3 | 560 / 379 / 44 / 0 |

Обе сборки — 0 критических предупреждений. У SCR1 такт DUT идёт через отдельный `BUFGCE`
(7058 нагрузок), тайминг между замораживаемым и основным доменами закрыт. BRAM платформы у SCR1 —
буферы: программа 16384 × 64 бит и поток инструкций 4096 × 160 бит. 80 МГц — частота, на которой SCR1
уже работал на этой плате в дизайне с PS; предел для окружения OCV не искали.

На плате проверено 2026-09-29: `--info` и все прогоны обоих окружений — PASS (ниже).

## Перенос на другую плату

Новая плата — это новый каталог `platforms/<плата>/` с тем же набором: блок-дизайн с мостом
PS → AXI4-Lite, верхний модуль с `OCV_ENV`/`OCV_AW`, сборка и адрес окна в `run.sh`. Ядро
платформы (`hw/`, `sw/`, `gen/`) и описания DUT не меняются. `OCV_USE_BUFGCE` подходит для
7-series, UltraScale(+) и Versal.

## Профиль стороны PS (`--profile`)

`run.sh ... --profile` печатает время и число обращений к шине по фазам прогона и отдельно
измеряет цену одного обращения. SCR1, dhrystone на плате (всего 0.567 с):

| Фаза | Время, с | Доля | Обращений | Из них шина, с |
|---|---|---|---|---|
| стимулы (генератор модели) | 0.010 | 1.7% | — | — |
| загрузка стимулов (запись) | 0.004 | 0.7% | 32 773 записи | 0.004 |
| ожидание DUT (опрос) | 0.004 | 0.7% | 14 177 чтений | 0.006 |
| слив выходов (чтение) | 0.275 | 48.6% | 659 605 чтений | 0.258 |
| эталонная модель | 0.199 | 35.2% | — | — |
| сверка | 0.075 | 13.2% | — | — |

Цена обращения (`ocv_busbench`, A72 → `M_AXI_LPD` → SmartConnect → хаб на 80 МГц):

| Доступ | нс на 32-битное слово |
|---|---|
| чтение 32 бит (так сейчас читает прогонщик) | 392 |
| запись 32 бит | 113 (запись не ждёт ответа) |
| копирование 64-битными чтениями | 214 |
| копирование 128-битными чтениями (`ldp`) | 126 |
| `memcpy` окна буфера | 94–96 |

Чтения к окну устройства выполняются строго по одному, поэтому чтение стоит полной задержки пути
(~400 нс), независимо от адреса; выигрыш даёт ширина одного обращения. SmartConnect отдаёт при
64- и 128-битном чтении те же данные, что при пословном (проверено на плате сравнением).

Выводы: слив буферов вчетверо ускоряется блочным чтением без изменений ПЛИС; после этого время
определяют модель и сверка на A72 — это программная работа (поля по именам, общий путь сверки).

```bash
aarch64-linux-gnu-gcc -O2 -static -Iocv/sw/include sw/board/ocv_busbench.c sw/lib/ocv_bus_mmap.c -o ocv_busbench
# на плате, после любого прогона (буфер не должен меняться):  ./ocv_busbench --base 0x80000000 --slot 2
```
