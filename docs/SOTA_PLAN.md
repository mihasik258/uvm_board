Сводный документ по итогам четырёх литературных обзоров (октябрь 2026, субагенты: RISC-V/эталонные
модели; UVM/ускорение/Verilator; FPGA-SoC ко-симуляция; площадки и артефакты). Все ссылки проверены
прямой загрузкой (встроенный web_search в сессиях субагентов был сломан — 401; обход: arXiv API,
OpenAlex, GitHub API, DVCon proceedings). Основа: код и документы репозитория (README, docs/*,
review_and_plan.md, research_notes.md разделы 11–12).

### 1.2. Слабые места (что увидит рецензент)

1. **Ускорения посчитаны против слабой базы.** ×76/×135 смешивают выигрыш методики (уход от UVM на
   каждом такте) и выигрыш железа. Разделить: база = (а) чистый UVM core-v-verif на ПК, (б) новый
   контур OCV на ПК (DUT в Verilator), (в) ферма N процессов + `--threads` на всех ядрах ПК,
   (г) плата. Сейчас (б) и (в) частично есть, но не в одной таблице.
2. **ARM — предел контура** (модель 91–94% времени на длинных программах). Не спрятать, а показать
   профиль и ablation (это уже сделано частично — оформить).
3. **Одна плата.** Второй платы нет; нужен аргумент переносимости (AXI4-master + AXI4-Lite —
   переносимы на Zynq/MPSoC; FireSim уже поддерживает Versal V80 — «мы на Versal» само по себе не новость).
4. **RV32-ядра.** CVA6 cv32a60x — уже приличный объект (out-of-order completion, кэши, hpdcache,
  AXI-64), но до XiangShan (DiffTest-H) далеко; смягчается реальными найденными багами.
5. **Репозиторий**: нет ни одного git-коммита, часть путей ведёт вне проекта (`pvo_scr1/ext`,
   `fpga/alinx_ve2302`), правки SCR1 не оформлены патчем. Для артефакта — блокер.
6. **Хвосты**: тест 1 (UVM core-v-verif) на плате прошёл, но dhrystone упирается в виртуальную
   периферию; mac16 ×0.5 — честная граница; покрытие covergroup «по изменению» — не сделано.

## 2. Карта конкурентов (2024–2026), с числами

### 2.1. Прямые архитектурные конкуренты (гибридная СнК / FPGA + эталон)

### 2.2. Верификационные фреймворки и фаззинг (бейслайны генерации)

- **GoldenFuzz** (NDSS'26, 2512.21524): сначала фаззится быстрая «золотая» модель, потом DUT;
  Rocket/BOOM/**CVA6**; восстанавливает все известные + 5 новых багов. Концептуально = роль
  интерпретатора OCV; цитировать и, если возможно, гоняться.
- **MorFuzz** (USENIX Sec'23): стандартный бейслайн фаззинга (17 багов, 13 CVE); **DifuzzRTL**;
  **ProcessorFuzz**; **SimFuzz** (2601.11838: 17 багов, 7 CVE; критика плато покрытия — учесть);
  **ReFuzz** (NDSS'26, 2512.04436: перенос баг-тестов между процессорами);
  **HiFuzz** (ITC'26, 2607.06619, RL); **ChatFuzz** (2404.06856, LLM+RL);
  **VSpector** (2609.23517: LLM против текста спецификации, 42 новых бага **CVA6**/XiangShan без
  эталона — класс оракула, дополнительный к lock-step).
- **XFuzz/DiffTest** (RISC-V Summit EU'25): открытый ко-сим + фаззинг, сотни багов; ближайший
  открытый аналог методологии.
- **HWFuzz** (RISC-V Summit EU'25): синтезируемый фаззер-IP в ПЛИС.

### 2.3. Эталонные модели и экосистема RISC-V

- **Spike** — золотой стандарт; **sail-riscv** — активен, официальный tech-golden-model (ACT/act4
  генерируется из него); MachCSL (2609.04043) нашёл баги **в самом Sail** → сильнейший аргумент за
  мульти-оракульность OCV (Spike + свой ISS/JIT; добавить Sail как третий).
- **Dromajo** — фактически заморожен (последние содержательные коммиты 2024), RV64 — честно
  зафиксировать в related work. **FORCE-RISCV** — дормант с 2023. **RISCOF** — архивирован;
  **riscv-arch-test** перешёл на ветку act4 (активна 10.2026).
- **RVVI** — активная стандартизация (riscv-verification/RVVI, пуш 09.2026), поддержан
  Synopsys/ImperasDV. У OCV RVFI — нужен раздел «RVFI сейчас, RVVI-адаптер как roadmap».
- **ImperasDV** (теперь Synopsys): lock-step + «pipeline synchronization» для асинхронных событий —
  методологический образец обработки прерываний (наш класс багов #3175).
- **core-v-verif** — активен (openhwfoundation), наш объект переноса.

### 2.4. UVM / ускорение / открытые инструменты

- **Verilator 5.052** (09.09.2026): UVM **2020-3.2** + Thread PGO + NUMA. UVM-на-ARM стал
  мейнстримно-возможным; наш патч-набор надо перепроверить против свежих версий и максимально
  upstream-ить (наши исправления Verilator — вклад сами по себе).
- **riscv-dv на eUVM** (DVCon'25 1008): ~1 млн инструкций/с генерации против ~10k на SV — бейслайн
  скорости генератора. Наш встроенный решатель (×130 к z3, равномерность распределения) —
  измерить в инструкциях/с против обоих.
- **Коммерческий TBA**: Aldec HES-DVM 130× (NoC+UVM), Xcelium+Palladium 107.84× (Cortex-M-33);
  SCE-MI 2.4 заморожен. DVCon'26 сместился к AI/ML и PSS — TBA «зрелый», ниша открытого
  дешёвого TBA-аналога свободна.
- **PSS 3.0** (утв. 08.2024), open-source реализации нет; PSS-мост OCV (те же стимулы в
  сим/плате/кремнии) — стандарт-совместимая рамка будущего.
- **pyuvm/cocotb** — альтернатива «UVM на медленном интерпретаторе» (сравнение для UVM-на-ARM).
- **SIMT-Aware UVM-lockstep для Vortex GPGPU** (2609.13311, 09.2026): lock-step + UVM + покрытие +
  fault-injection **в симуляции** — ослабляет «первый lock-step+UVM», но НЕ аппаратную часть.
  Обязательно процитировать для границы.

### 2.5. Инфраструктура

- **FireSim 2026**: миграция AWS F1→F2, поддержка Versal-класса (Alveo V80) — «Versal» само по себе
  не новость; новость — NoC-DMA транспорт + гибридный PS.
- **GSIM** (2508.02236): ×7.34 Verilator для XiangShan — программная альтернатива; учесть в бейслайнах.
- **Chrono-Fabric** (FPGA'26): мульти-FPGA координация — задел для масштабирования.
- XiangShan difftest: расширение проб (Vector/Matrix/TLB/RefillTest), Palladium, XFuzz — «конвергенция
  к нашей территории», следить.

## 3. Анализ новизны: что можно заявлять, а что нет

### 3.1. Что уже ЗАНЯТО (не заявлять как новизну)

1. «Lock-step с эталоном при DUT в ПЛИС» — DiffTest-H, Lyra, FERIVer, ENCORE.
2. «Свёртка/батчинг событий ко-симуляции» — DiffTest-H (Squash), у нас CRC-окна как реализация.
3. «Весь цикл фаззинга в железе» — TurboFuzz, HWFuzz.
4. «Versal как платформа» — FireSim V80.
5. «Clock-gating DUT для ко-эмуляции» — ZynqParrot.
6. «UVM+lock-step+покрытие+fault injection в симуляции» — Vortex-SIMT (2609.13311).

### 3.2. Что ОТКРЫТО и есть у нас (клэймы статьи)

**C1. Полный UVM на ARM самой СнК рядом с DUT в ПЛИС.** Ни одна работа 2024–2026 не исполняет
сторонний UVM-тестбенч (методология, sequences, scoreboard, покрытие) на процессоре гибридной СнК
с ядром в ПЛИС. Все аналоги: C/C++/Python (ZynqParrot, FERIVer, Hercules, Lyra) или UVM на x86-хосте
(TBA/эмуляторы, distributed-UVM AMD — x86-процессы). Verilator 5.052 (UVM 2020) делает это впервые
реализуемым — мы первые реализовавшие. Тест «как есть» (lockstep.py) доказывает бесшовность
(совпадение с ПК до такта), ускоренный вариант — выигрыш.

**C2. Эталонная модель как JIT под PS.** JIT RV32IMC→AArch64 на A72 — никто не публиковал JIT
эталон в ко-симуляции на кристалле (FERIVer — QEMU TCG; Lyra — модель в ПЛИС; XiangShan — C++ на
x86-хосте). Плюс мульти-оракул (Spike кросс-чек) — против «насколько золотой ваш золотой»
(прецедент: баги в самом Sail).

**C3. Генерическая no-RTL-edit обёртка ядра (.bind) для трёх разнотипных ядер** в одном контуре
функциональной верификации — в литературе нет (ZynqParrot — perf; у каждой статьи один DUT).

**C4. FPGA-платформа с мутационными кампаниями + реальными багами + воспроизводимым бенчмарком
багов.** Публичного CPU-bug-бенчмарка нет (поле: CVE-списки MorFuzz, seed-корпус SimFuzz, recovery-set
GoldenFuzz — всё не переигрываемо). Упаковать #3175 + flushed_load + stale_load + исторические баги
CVA6/CV32E40P (откат фиксов) в релиз «RISC-V core bug benchmark v1» — дешёвый вклад с высокой
цитируемостью, которого ждёт поле.

**C5. Открытый дешёвый аналог TBA/SCE-MI на гибридной СнК** («SCE-MI for the poor»): транзакционный
канал ARM↔ПЛИС поверх AXI/DMA, хост — ARM вместо рабочей станции; SCE-MI 2.4 заморожен, открытых
аналогов нет. Рамка для методологии.

Чего НЕ заявлять: «быстрее эмулятора/фермы ПК вообще»; заявлять: **цена/пропускная способность
($/MIPS сверенной команды)**, латентность (AXI против PCIe/Ethernet), конвейерность, ниша C1.

### 3.3. Обязательные таблицы статьи (что потребует рецензент)

T1. Заголовная: платформа против (a) чистый UVM на ПК, (b) OCV-контур на ПК (DUT в Verilator),

## 4. План работ до SOTA (приоритеты, критерии готовности)

### Этап 0. Репозиторий и воспроизводимость (блокер артефакта; ~2–3 дня)

1. Первый коммит; всё внешнее — `tools/get_*.sh` по фиксированным хешам; правки SCR1 — патчем;
   пути `pvo_scr1/ext`, `fpga/alinx_ve2302` — заменить на `ext/`.
2. CI (GitHub Actions): test_all.sh (FAST=1) на каждый пуш.
3. README-артефакт: версии (Vivado 2023.2, Verilator 5.052, toolchain), карта воспроизведения.
4. Анонимный репозиторий (anonymous.4open.science) под дабл-блайнд ревью.

Критерий: чистый клон + `tools/get_*.sh` + `test_all.sh` = PASS на машине без истории.

### Этап 1. Честные бейслайны и полные таблицы (главное для статьи; ~1 неделя, плата не нужна)

1. Одна методика замеров: те же программы (riscv-dv/сгенерированные/Embench/coremark/dhrystone),
   медианы ≥3 прогонов, governor performance, taskset на P-ядро, полный конфиг фермы.
2. Замерить на ПК: (а) чистый UVM core-v-verif, (б) OCV-контур Verilator, (в) ферма 22 процессов +
   `--threads` (есть `tools/baseline_pc.sh` — доработать и включить в таблицу), (г) GSIM как
   справочный столбец (опционально).
3. Собрать T1–T7 из §3.3 в `docs/PAPER_TABLES.md` с сырыми логами в `build/board_results/`.
4. Кривые покрытия: сгенерированные программы CVA6/CV32E40P/SCR1, случайная против directed,
   бины/с; сравнение с eUVM (1 млн инстр/с генерации) и TurboFuzz (×2.23) хотя бы качественное.

Критерий: таблица T1 закрывает все четыре базы; разделение «методика vs железо» видно из неё без
пояснений.

### Этап 2. Усиление UVM-клэйма C1 (главный актив; ~1–2 недели)

1. Тест 1 на плате: добить dhrystone — виртуальная периферия в ПЛИС (печать через буфер, статус,
   конец) чтобы ARM видел только редкие события; замер «до/после».
2. mac16: добить `randomize()` на ARM (остаток ~60 мкс/вызов: VlRandomizer копирование, write_var)
   — либо честная граница с числом.
3. Покрытие covergroup «по изменению» (FPGA присылает запись при изменении отслеживаемого сигнала;
   бины те же) — закрыть пункт плана из docs/UVM.md §6.
4. Проверить сборку core-v-verif на свежем Verilator (UVM 2020-3.2): сколько наших патчей уже
   не нужны; ненужные — выпороть, нужные — оформить upstream (PR в Verilator — плюс к статье и
   снижение поддерживаемого форка).
5. Обновить таблицу путей A–E (docs/UVM.md) числами платы 13–14.10.

Критерий: чужой тестбенч без правок — на плате быстрее лучшего ПК-варианта того же тестбенча
(по крайней мере на coremark-классе программ); список допущений — полный.

### Этап 3. Горячий путь ARM: снять предел модели (продолжение 6б.9; ~2–3 недели, нужна плата)

1. Перенести технику UVM-пути (движок A) в прогонщик: LTO уже есть; свёртка на месте, раздача
   записей из JIT-кода без промежуточных структур, batch emit — цель ~≤100 нс/команду сверх кода
   JIT, т.е. ARM ≥10 млн команд/с.
2. Разобрать профиль: check_window+CRC 32% → сравнение на месте при DMA (уже спланировано) или
   сравнение в ПЛИС (вариант ENCORE: ARM кладёт ожидаемые записи в DDR, ПЛИС сверяет) — выбрать
   по замеру.
3. Второе ядро A72: конвейер «модель/сверка» или 2 копии DUT с двумя моделями (ресурсов ПЛИС
   хватает: CVA6 ~10.5k LUT из 150k) — ×2 на регрессии независимых программ.
4. Идея ISAAC (не отозванная часть): один REF → N копий DUT — с двумя A72 теперь ложится.

Критерий: на CVA6-регрессии ≥10 млн сверенных команд/с (сейчас ~3–6.5); профиль: модель-код
>50% времени (т.е. обвязка перестала доминировать).

### Этап 4. Bug-бенчмарк и реальные ошибки (клэйм C4; ~1–2 недели)

1. Упаковать: #3175 (mie), flushed_load_min, stale_load_min (+v5), плюс 5–10 исторических багов
   CVA6/CV32E40P (откат фиксов по трекеру, скрипт репродукции) — формат: ELF/hex + ожидаемое
   поведение + скрипт прогона + логи.
2. Мутационные кампании на плате против ПК: время-до-обнаружения каждой ошибки, тот же seed.
3. Метрика «время от бага до волны» (плата → VCD на ПК): замерить и включить.
4. Опционально: third oracle — sail-riscv как кросс-чек ISS/JIT на подмножестве (MachCSL-аргумент).

Критерий: бенчмарк воспроизводится одной командой из чистого клона; таблица «плата нашла за N
мин — ПК за M часов» по каждому багу.
