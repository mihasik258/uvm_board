# Любое процессорное ядро под OCV

Обёртка одна для всех ядер: память, загрузчик программы, управление запуском, переходники шин, окна
устройств, входы по расписанию и потоки того, что делает ядро. От ядра нужен только файл привязки — какие
у него имена. RTL ядра не меняется.

```
файл привязки (core.bind) ──► gen/cpu_wrap.py ──► <name>_dut.sv   обёртка (ПЛИС и симуляция)
                                                  <name>.json     каналы OCV
                                                  ocv_cpu_wrap.h  ядро для модели (models/cpu/ocv_cpu_model.c)
                                                  ocv_cpu_pc.h    потоки для эталона на ПК (pc/tb_pc.cpp)
                                                  wrap.env        файлы RTL, модель, генератор - для скриптов
```

| часть | файл |
|---|---|
| память 2^AW слов, два порта, загрузчик на порту A; блочная или UltraRAM (`memory ... uram`) | `ocv_cpu_ram.sv` |
| шина OBI → порт памяти; окна устройств; случайные задержки; проверка протокола | `ocv_obi_mem.sv` |
| шина AXI4 (32 или 64 бита) → порт памяти: пакеты FIXED/INCR/WRAP, узкие передачи, WSTRB; окна устройств; задержки; проверка протокола | `ocv_axi_mem.sv` (свой тест: `test/axi_mem.sh`) |
| модель для любого ядра: программа (ELF/hex/bin) или генерация, разбор по потокам, устройства, прерывания, покрытие | `models/cpu/ocv_cpu_model.c`, `models/cpu/cpu_streams.h` |
| эталон на ПК: та же обёртка в Verilator, та же модель, без хаба | `pc/tb_pc.cpp` |
| запуск: ко-симуляция, эталон на ПК, образ VD100 | `run.sh <bind> cosim\|pc\|vd100` |
| SD-карта на несколько ядер, прогон на плате | `make_sd.sh`, `board_run.sh` |

## Привязка

Полное описание директив — в начале `gen/cpu_wrap.py`. Главное:

| директива | что |
|---|---|
| `files <list> VAR=...` / `rtl` / `rtl.sim` / `rtl.fpga` | RTL ядра (списки файлов с `+incdir+`, вложенными `-F`/`-f`) |
| `clock`, `reset`, `tie <port> = <expr>` | такт, сброс, постоянные входы (не названный вход = 0, список в `report.txt`) |
| `bus obi\|axi A\|B <prefix> [ro] [dev]` | шина ядра по префиксу имён; ширина AXI — по ширине `rdata`; `dev` — через неё окна устройств |
| `memory <bytes> [at <base>] [uram]` | области RAM (несколько — разреженная карта); после сброса обёртка их чистит, программа приносит только ненулевые слова |
| `device <name> <base> <bytes>` | окно устройства: доступы ядра идут процессору (запись — без ожидания, чтение — такт ядра стоит до ответа) |
| `input <port> [irq] [= v]` | вход ядра по расписанию от процессора (`irq` — линии прерываний, расписание даёт генератор) |
| `latency` | случайные задержки памяти (`--model-opt lat=G,R`) |
| `boot`, `exit`, `stop` | адрес старта; конец — переход на `exit` и/или запись в `stop` (`exit none` — только запись) |
| `model <ISA>[:профиль]`, `gen cv32\|scr1` | эталонная модель (`:cv32e40p`, `:cva6`) и генератор программ |
| `logic` | свой код SV в обёртке (регистры для потоков) |
| `stream <канал> <вид> [опции]` | поток: `valid = ...` и поля |

`@x` в выражениях — порт ядра `x` или сигнал внутри ядра (`core_i.x`).

Виды потоков (одинаковые для обёртки и модели, `models/cpu/cpu_streams.h`):

| вид | поля | что это |
|---|---|---|
| `retire` | pc pc_next insn rd rd_wdata trap | одна запись на выполненную команду (RVFI) |
| `issue` | pc insn c | команды по порядку программы (ловушки — только ecall/ebreak; `ecall` — только ecall) |
| `regw` | rd data | записи регистров (`load` / `nonload` — только загрузки / всё, кроме них) |
| `store` | addr be data | записи в память, как их несёт 32-битная шина |
| `interrupt` | cause (+seq) | ядро взяло прерывание; seq — сколько команд было до него (модель берёт его там же) |
| `csrr` | data | чтения CSR в регистр: изменчивые CSR (mip, счётчики) модель берёт отсюда, остальные сверяет |
| `watch` | value | значение ядра при изменении (покрытие, мониторы) |
| `error` (всегда, `proto`) | value | нарушение протокола шины — модель ждёт ни одного |

`interrupt`, `csrr`, `watch`, `error` идут запись за записью; остальные при `--squash N` сворачиваются в
подписи окон по N записей.

## Ядра

| ядро | привязка | шины | потоки | проверено |
|---|---|---|---|---|
| CV32E40P (OpenHW) | `examples/cv32e40p/cv32e40p.bind` | OBI ×2 | issue, regw ×2, store, irq, csrr, watch | генерация с CSR/ловушками/RVC/невыровненными/19 линиями прерываний (100% покрытия), программы core-v-verif (hello, dhrystone, coremark), 7 внесённых ошибок найдены |
| SCR1 (Syntacore) | `examples/scr1/scr1.bind` | AXI4-32 ×2 | retire (RVFI-lite) | генерация (100% покрытия), hello, dhrystone, с задержками памяти |
| CVA6 (OpenHW, cv32a60x) | `examples/cva6/cva6.bind` + `cva6_ocv_core.sv` (только раскладка портов) | AXI4-64 | issue, regw, store, irq, csrr (из RVFI) | обёртка генерируется; модель `:cva6` и генерация проверены (fast = jit); ко-симуляция — в работе |

## Запуск

```bash
hw/cpu/run.sh examples/cv32e40p/cv32e40p.bind cosim gen:directed -- --batches 6 --reset-each-batch
hw/cpu/run.sh examples/scr1/scr1.bind pc examples/scr1/programs/dhrystone21.hex
hw/cpu/run.sh examples/cv32e40p/cv32e40p.bind vd100        # образ ПЛИС + программа PS
hw/cpu/make_sd.sh -o /tmp/sd examples/cv32e40p/cv32e40p.bind <программы> -- examples/scr1/scr1.bind
```

Сгенерированные программы идут со сторожем `--max-cycles` (по умолчанию 50 млн тактов на программу,
`OCV_MAX_CYCLES`): ядро, которое не может закончить (например, зациклилось в обработчике прерываний),
даёт FAIL с первой расходящейся записью, а не крутится часами.

На VD100 большие буферы хаба (от 147456 бит, `OCV_URAM_BITS`) кладутся в UltraRAM — блочной памяти
кристалла (155 RAMB36) иначе не хватает на ядро с большой RAM и широкими потоками.
