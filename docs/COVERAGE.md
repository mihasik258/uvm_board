# Покрытие верификатора на плате (PRODUCT_PLAN, раздел 2)

## Что считает тестбенч CVA6 (core-v-verif)

Опись исходников, 20.10.2026. Пути: `ext/cva6/verif`, `ext/core-v-verif/lib/uvm_agents/uvma_isacov`.

**Цепочка одна.** RVFI → монитор isacov → `uvma_isacov_instr_c` → модели покрытия.

**`uvma_isacov_cov_model`** (агент isacov):
- 53 типа covergroup, для cv32a60x около 132 экземпляров;
- на команду срабатывает одна covergroup своего семейства (`sample()`, выбор по имени команды) и
  `cg_sequential`.

**Модели CVA6** (`env/uvme/cov`):
- исключения (`cause`, `trap`, имя, группа, запись CSR, `mem_addr[1:0]`);
- недопустимые команды (поля слова команды при `cause == 2`);
- прерывания (CSR `mcause`/`mstatus`/`mie`/`mip` из RVFI);
- конфигурация и сброс;
- AXI;
- ISA (только Zicond, у cv32a60x выключено).

**Конструкции:**
- coverpoint по полям, `bins x[] = {[a:b]}`;
- `ignore_bins`/`illegal_bins ... with (...)` с аргументами конструктора;
- `iff`, cross, `binsof ... intersect`;
- побитные бины `ISACOV_CP_BITWISE`: бит i был 0 и был 1, на rs1/rs2/rd и непосредственных значениях;
- `option.per_instance`. Нет `at_least`, `weight`, `goal`.

**Состояние:**
- `cg_sequential` читает 1–3 предыдущие команды (выборка, история сдвигается только для выбранных
  команд);
- AXI-ext — очереди транзакций;
- сброс — переход между состояниями.

**Поля команды:**
- из слова команды (дизассемблер Spike через DPI, таблицы `tdefs`): имя, тип, группа, регистры,
  непосредственные значения и их классы;
- из значений RVFI: `rs1/rs2/rd_value` и их классы — ноль, знак (`get_instr_value_type`);
- `mem_addr[1:0]` — для группы невыровненных обращений;
- `trap` и `cause`.

**Ошибки, найденные в самом покрытии core-v-verif** (не отправляем; для диплома). Подробнее — в отчёте описи.
1. AMOMINU выбирает covergroup AMOMAXU.
2. `is_csr_write` у CSRRSI/CSRRCI смотрит `immu` (с адресом CSR), а не uimm.
3. Дизассемблер не знает Zbc, Zbs, Zcb: их covergroup всегда пусты.
4. Бин `NrPMPEntries = {8}` недостижим для cv32a60x.
5. Узкие побитные макросы применены к 32-битным полям.
6. Перекрытие ignore/bins у INSTR_ADDR_MISALIGNED при RVC.

## Способ: модель на плате собирает классы, исходные covergroup считают бины

**Перевод SV на C не нужен.**

1. **Ключ команды** (код на C в модели, горячий путь). Слово команды, `trap`/`cause`, `mem_addr[1:0]`,
   классы значений rs1/rs2/rd (ноль; старший бит; иначе) и тот же ключ предыдущей выбранной команды (для
   `cg_sequential`). Различных ключей — тысячи и десятки тысяч, а не миллиарды.
2. **Побитные бины.** Для каждого ключа модель копит OR и AND значений rs1/rs2/rd (биты, бывавшие 1, и
   биты, бывавшие 0). Пара представителей со значениями OR и AND даёт ровно те же побитные бины, что все
   команды класса. Если OR/AND выходит из класса значения (AND = 0 у ненулевого класса), берутся
   дополнительные представители.
3. **Счётчики** — точные на ключ (сколько команд класса).
4. **Отчёт.** В конце прогона исходные модели покрытия тестбенча, собранные Verilator'ом, получают по одной
   настоящей записи RVFI на ключ (первая встреченная) и представителей OR/AND:
   - бины и проценты — те же, что при выборке каждой команды;
   - счётчики повторов в отчёте covergroup — нет, они в таблице ключей.
5. **Проверка допущений — скриптом по исходникам covergroup.** Значения RVFI читаются только через классы
   значений и побитные макросы. Что не так — эта covergroup выбирается на каждой команде как есть (с причиной
   в отчёте).
6. **Прерывания** (CSR из RVFI) — редкие команды: выбираются каждая, полностью.
7. **Приёмка.** Короткие программы на ПК: отчёт «каждая команда в covergroup» = отчёт «ключи и
   представители», по каждому экземпляру covergroup. Затем длинный тест на плате.
