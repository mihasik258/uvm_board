## Проект и цель

Дипломный проект OCV. Плата ALINX VD100 (ПЛИС + ARM A72) проверяет RISC-V ядра длинными прогонами:
- каждая команда сверяется с эталонной моделью;
- быстрее фермы ПК (CVA6: ошибка `minstreth` на плате за 5,2 мин против 8,3 ч на ПК, ×95);
- подключение ядра без ручной работы.

Главный документ — `docs/PRODUCT_PLAN.md`. Сейчас идёт раздел 2: **покрытие — бины верификатора, а не наши.**
Собственные covergroup тестбенча CVA6 из core-v-verif (isacov и модели CVA6) считаются по записям RVFI
от нашей модели. Подробности и все замеры — в `docs/COVERAGE.md`, прочитай его целиком.

Владелец хочет довести результат до уровня, пригодного для научной статьи. Поэтому:
- методы должны быть общими, выводиться автоматически из исходников и проверяться;
- ручной код под одну библиотеку — только если без него нельзя, и тогда с автоматической проверкой;
- каждое утверждение подкрепляется замером и проверкой точности против эталона «каждая команда».

## Подготовка окружения

1. `tools/get_verilator.sh` — Verilator с патчами в `build/verilator`.
2. `tools/get_cores.sh` — ядра и core-v-verif в `ext/`.
3. `examples/cva6/cov/cov.sh build`: около 7 мин и **16 ГБ памяти**. Если памяти меньше — скажи мне,
   не урезай сборку молча.
4. Записи: `hw/cpu/run.sh examples/cva6/cva6.bind bench -- --model-opt gen=directed --model-opt cpu=fast
   --model-opt rvfi_out=<файл> --batches 100`. Это около 5,2 млн команд, ~250 МБ.
5. Эталон: `cov.sh run <файл> g100`.
6. Таблица полей: `verilator -E -P` по исходникам covergroup вместе с `uvma_isacov_macros.sv`, затем
   `tools/cov/cov_fields.py ... --json fields.json`.
7. Имена Spike: `tools/cov/spike_names.cpp`, слинкованный с объектами дизассемблера из `build/cov/cva6/dasm`.
8. Бины конфигурации: прогон обвязки на пустом файле записей (`+ocv_cov_report=bins.rep`).
9. Запуск прототипа:
   `cov_filter_proto.py fields.json names.txt records.rvfi kept.rvfi bins.rep sampled_names.txt`.
   `sampled_names.txt` — метки `case` функции `uvma_isacov_cov_model_c::sample`, способ получения — в
   истории `docs/COVERAGE.md`.

## Правила владельца (обязательно)

- Работай только внутри репозитория. Не лезь в другие папки машины.
- Перед каждым долгим или тяжёлым запуском ставь `ulimit -v`: на сборку обвязки 16000000, на прогоны
  8000000. Следи за ростом памяти. Сборки Vivado параллельно не запускай.
- Трассу CVA6 пиши в /dev/null.
- **Коммиты без строки `Co-Authored-By`.** Работай в ветке `coverage-filter`, в `main` не коммить.
  Пушит владелец; если без пуша ветки работу не передать — спроси.
- Не отправляй отчёты об ошибках в чужие проекты (core-v-verif, Verilator, CVA6). Найденные ошибки
  записывай в `docs/COVERAGE.md`.
- Никаких паролей и ключей.
- **Новое направление** (другой метод, второе ядро A72, копии DUT, частота ПЛИС, перенос тестбенча
  целиком) — сначала предложи и жди ответа. Технику внутри задачи выбирай сам.
- Не ускоряй тест A и короткие тесты: важны только длинные.
- `docs/SOTA_PLAN.md` и `docs/IMPROVEMENT_PATHS.md` — только для чтения, это идеи.
- Плата сейчас не подключена: всё, что требует `/dev/ttyUSB0`, отложи и запиши, что осталось проверить.
- Пиши код в стиле окружающего: плотность комментариев, имена, идиомы.
- Сообщай результат честно: что проверено, что нет, с цифрами. Если тест падает — покажи вывод.
