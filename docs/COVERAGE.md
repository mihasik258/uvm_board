# Покрытие верификатора на плате (PRODUCT_PLAN, раздел 2)

## Что считает тестбенч CVA6 (core-v-verif)

Опись исходников, 20.10.2026. Пути: `ext/cva6/verif`, `ext/core-v-verif/lib/uvm_agents/uvma_isacov`.

**Цепочка одна.** RVFI → монитор isacov → `uvma_isacov_instr_c` → модели покрытия.

**`uvma_isacov_cov_model`** (агент isacov):
- 53 типа covergroup, для cv32a60x около 132 экземпляров;
- на команду срабатывает одна covergroup своего семейства (`sample()`, выбор по имени команды) и
  `cg_sequential`.

**Модели CVA6** (`env/uvme/cov`):
- исключения (`cause`, `trap`, имя, группа, запись CSR, `mem_addr[1:0]`);
- недопустимые команды (поля слова команды при `cause == 2`);
- прерывания (CSR `mcause`/`mstatus`/`mie`/`mip` из RVFI);
- конфигурация и сброс;
- AXI;
- ISA (только Zicond, у cv32a60x выключено).

**Конструкции:**
- coverpoint по полям, `bins x[] = {[a:b]}`;
- `ignore_bins`/`illegal_bins ... with (...)` с аргументами конструктора;
- `iff`, cross, `binsof ... intersect`;
- побитные бины `ISACOV_CP_BITWISE`: бит i был 0 и был 1, на rs1/rs2/rd и непосредственных значениях;
- `option.per_instance`. Нет `at_least`, `weight`, `goal`.

**Состояние:**
- `cg_sequential` читает 1–3 предыдущие команды (выборка, история сдвигается только для выбранных
  команд);
- AXI-ext — очереди транзакций;
- сброс — переход между состояниями.

**Поля команды:**
- из слова команды (дизассемблер Spike через DPI, таблицы `tdefs`): имя, тип, группа, регистры,
  непосредственные значения и их классы;
- из значений RVFI: `rs1/rs2/rd_value` и их классы — ноль, знак (`get_instr_value_type`);
- `mem_addr[1:0]` — для группы невыровненных обращений;
- `trap` и `cause`.

**Ошибки, найденные в самом покрытии core-v-verif** (не отправляем; для диплома). Подробнее — в отчёте описи.
1. AMOMINU выбирает covergroup AMOMAXU.
2. `is_csr_write` у CSRRSI/CSRRCI смотрит `immu` (с адресом CSR), а не uimm.
3. Дизассемблер не знает Zbc, Zbs, Zcb: их covergroup всегда пусты.
4. Бин `NrPMPEntries = {8}` недостижим для cv32a60x.
5. Узкие побитные макросы применены к 32-битным полям.
6. Перекрытие ignore/bins у INSTR_ADDR_MISALIGNED при RVC.

## Способ: модель на плате собирает классы, исходные covergroup считают бины

**Перевод SV на C не нужен.**

1. **Ключ команды** (код на C в модели, горячий путь). Слово команды, `trap`/`cause`, `mem_addr[1:0]`,
   классы значений rs1/rs2/rd (ноль; старший бит; иначе) и тот же ключ предыдущей выбранной команды (для
   `cg_sequential`). Различных ключей — тысячи и десятки тысяч, а не миллиарды.
2. **Побитные бины.** Для каждого ключа модель копит OR и AND значений rs1/rs2/rd (биты, бывавшие 1, и
   биты, бывавшие 0). Пара представителей со значениями OR и AND даёт ровно те же побитные бины, что все
   команды класса. Если OR/AND выходит из класса значения (AND = 0 у ненулевого класса), берутся
   дополнительные представители.
3. **Счётчики** — точные на ключ (сколько команд класса).
4. **Отчёт.** В конце прогона исходные модели покрытия тестбенча, собранные Verilator'ом, получают по одной
   настоящей записи RVFI на ключ (первая встреченная) и представителей OR/AND:
   - бины и проценты — те же, что при выборке каждой команды;
   - счётчики повторов в отчёте covergroup — нет, они в таблице ключей.
5. **Проверка допущений — скриптом по исходникам covergroup.** Значения RVFI читаются только через классы
   значений и побитные макросы. Что не так — эта covergroup выбирается на каждой команде как есть (с причиной
   в отчёте).
6. **Прерывания** (CSR из RVFI) — редкие команды: выбираются каждая, полностью.
7. **Приёмка.** Короткие программы на ПК: отчёт «каждая команда в covergroup» = отчёт «ключи и
   представители», по каждому экземпляру covergroup. Затем длинный тест на плате.

## 2.3, фильтр в модели (21.10)

**Итог.** Модель пишет только записи, нужные покрытию тестбенча (`--model-opt rvfi_filter=<таблица>` рядом с
`rvfi_out`). Отчёт обвязки по ним совпадает с эталоном «каждая команда» по всем 148 экземплярам и по каждому
бину `coverage.dat`. Поля фильтра проверены против монитора isacov на каждой из 5,2 млн записей.

### Как устроено

- **Таблица фильтра генерируется, руками не пишется** (`examples/cva6/cov/cov.sh table` → `filter.tab`):
  - `cov.sh build` прогоняет исходники covergroup через `verilator -E` и `tools/cov/cov_fields.py`
    (`fields.json`): что читает каждый coverpoint (выражение, его `iff`, `iff` бинов, текст бинов) и правило
    истории isacov — метки `case` функции `sample()` по веткам (нормальная команда / ECALL-EBREAK с
    ловушкой) и по флагам конфигурации;
  - обвязка на пустом файле записей даёт элементы с бинами (`bins.rep`) и флаги конфигурации
    (`bins.chk`, первая строка);
  - `tools/cov/cov_filter_gen.py` (общая часть — `tools/cov/cov_proj.py`) собирает 58 проекций, 9
    побитных полей, имена, сдвигающие историю, и таблицу имён Spike.
- **Имена Spike без Spike в модели.** `tools/cov/spike_table.cpp` выгружает таблицу дизассемблера Spike в
  порядке поиска (корзины `w & 0x7f`, `w & 0xe003`, общая; внутри корзины — с конца; 2 777 записей). Модель
  ищет так же, с запоминанием по слову. Совпадение со Spike: 2 150 756 слов (150 756 из записей, 1 млн
  случайных 32-битных, 1 млн случайных 16-битных) — 0 расхождений.
- **Фильтр** (`models/cpu/ocv_cov_filter.c`, двойник прототипа):
  - компоненты записи — те же, что в `cov_proj.py`;
  - уровень 1: вектор компонентов, которые читают проекции (текущей записи и предыдущей записи истории),
    по 128-битному отпечатку. Уже виденный вектор ничего нового не даёт. Это только кэш перед уровнем 2:
    решение об отборе от него не зависит, кроме случая коллизии 128-битного отпечатка;
  - уровень 2 (только для нового вектора): каждая проекция с префиксом (имя, ловушка, прерывание), ключ
    хранится точно;
  - побитные поля: маски «был 1» / «был 0» на (имя, ловушка, прерывание);
  - запись с прерыванием — всегда;
  - контекст: записи назад до третьей, сдвинувшей историю isacov (её `instr_prev`, `prev2`, `prev3`).
- **Выход фильтра на C совпадает с прототипом на Python побайтно** (5 211 237 записей).

### Что было не так в прототипе (4 бина `cg_sequential`)

1. **Правило истории.** isacov сдвигает историю не только на нормальных командах, но и на ECALL / EBREAK /
   C.EBREAK с ловушкой, если `cause` (у монитора это `rvfi.trap >> 1`) равен 3, 8 или 11 — ветка
   `is_ecall_or_ebreak` в `sample()`. Прототип её не учитывал. На «AUIPC; EBREAK (ловушка); JAL» он считал
   пару JAL/AUIPC набранной, а у isacov там JAL/EBREAK. Настоящую пару (JAL обработчика по адресу 0x100
   после AUIPC и ловушки невыровненной загрузки, запись 2757) фильтр поэтому пропускал. Теперь правило
   выводится из `sample()`, оно же проверяется против isacov (ниже).
2. **Опасности для сжатых команд.** `is_raw_hazard` сравнивает номера регистров: для RVC монитор берёт
   rs1/rd = биты [11:7], rs2 = биты [6:2] (`rvc_rs1`, `rvc_rs2` Spike). Прототип сравнивал с ними всё слово,
   и признак опасности для RVC всегда был «нет»: 2 бина `cross_seq_gpr_raw_hazard`.
3. **Одноимённые covergroup.** `cg_rtype` есть и в isacov, и в `uvme_isa_covg` CVA6. `fields.json` хранил
   только последнюю по порядку файлов. Теперь повторное имя хранится как `имя@файл`, читаются обе (у
   CVA6-шной в этой конфигурации нет экземпляров).

### Проверка уточнений (функциональная зависимость)

- Обвязка, режим `cov.sh check` (`+OCV_CHECK=`): подписчик на `monitor.ap` пишет для каждой записи, сдвинулась
  ли история isacov, `raw_hazard` и `csr_hazard` (методы его модели) и значения 82 выражений coverpoint и
  условий, читающих только транзакцию. Функция печати генерируется из `fields.json`. Выражение,
  которое читают только covergroup, вызываемые из `sample()` по имени, вычисляется только для этих имён:
  `is_branch_taken()` на остальных командах завершает тест через `uvm_fatal`.
- `tools/cov/cov_check.py` на всех 5 211 237 записях:
  - история: правило фильтра = isacov, 0 расхождений;
  - `raw_hazard`, `csr_hazard`: однозначно задаются компонентами фильтра (с его предыдущей записью), 0
    расхождений;
  - 68 выражений-значений: (имя, ловушка, прерывание) + компоненты фильтра однозначно задают значение. Где
    компонент — класс значения (`rd_value` в SLT, `rs1_value` в делении), задают принадлежность литералам и
    диапазонам бинов (0, 1, `8000_0000`, `ffff_ffff`, `[0:1]`);
  - 12 побитных: значение, по которому фильтр копит маски, равно значению монитора. Для этого фильтр
    теперь хранит непосредственные значения так же, как монитор (`immb = sb_imm >> 1`,
    `immj = uj_imm >> 1`). Вывод фильтра от этого не изменился;
  - 2 выражения (`mem_addr[1:0]`, `mem_addr[0]` в чистом виде) в этой конфигурации не читает ни один
    coverpoint с бинами;
  - вне проверки: `inside {legal_i_opcode}` (член класса; его аргумент — сырые биты слова, они в
    компонентах как есть) и `instr_prev*` (их покрывает проверка истории).
- Проверка ловит ошибку: если убрать из таблицы ветку ECALL/EBREAK, на 100 программах снова теряются 2 бина
  `cross_seq_instr_x2`. На 4 программах шага 12 `test_all.sh` этой пары может не быть: шаг проверяет поля
  монитора на всех записях, но сверка отчёта на коротком тесте ловит не всё.

  `get_instr_group` для всех имён, проверка та же.
- **Цена фильтра** (в модели на ПК, ns на команду, 100 программ, три прогона): без записей — 90–115; все
  записи в /dev/null — 860–1 170; с фильтром — 780–990. Сам фильтр (записи заранее в памяти) — 0,63–0,69 мкс
  на запись. Основная цена записи — путь `rvfi_out` (покомандный режим, чтение CSR), фильтр заменяет печать
  и стоит примерно столько же. На A72 не мерил (плата не подключена). По порядку величины это микросекунды
  на команду: для длинных тестов на плате (2.5) в таком виде дорого — нужна оценка и, вероятно, другой
  уровень 1.
- **Сборка обвязки:** в этой машине 15,7 ГиБ, без swap Verilator убивается OOM (пик 14 ГБ ОЗУ + 5,4 ГБ swap
  при `OCV_MAKE_J=4`), 10–18 мин.

### Ещё одна находка в core-v-verif (8)

Монитор копирует в `instr.trap` только `rvfi.trap[0]` (поле `bit [13:0]`). Поэтому в `sample()` условия
`instr.trap[8:3]`, `instr.trap[11:9]`, `instr.trap[13:12]` всегда ложны:
- одиночный шаг отладки (`trap[11:9] == 4`) не считается нормальной командой;
- ECALL/EBREAK определяются только по `cause` (`rvfi.trap >> 1`).

Для CVA6 (`cause` = mcause) последнее работает. Не отправляем; записано для диплома.

### Осталось

- 2.5: ключи/фильтр в jit, цена в тесте A — только на плате (`/dev/ttyUSB0` не подключён).
- Уровень 1 грубее (группа команды вместо имени, поля сжатого слова вместо слова) — см. «Насыщения нет».
- 2.6 (CV32E40P, SCR1) — по согласию владельца.
