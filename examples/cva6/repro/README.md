# Направленные тесты CVA6

**13.10.2026: все три сбоя воспроизведены на ПЛИС** (VD100, ядро CVA6 в ПЛИС, модель на A72; не артефакт
Verilator): `mie_disable` — `ERRATUM: 7`, как на ПК; `flushed_load_min` — расхождение в обработчике
(ядро на 0x1b4, модель на 0x1b0) при задержках памяти 0/0, 2/3, 4/4; `stale_load_min` — `a6 = 1`,
`stale_load_min_v5` — `a6 = 5` вместо 0 при задержках 0/0 (при 2/3 и 4/4 на ПЛИС проходит). Сгенерированный
тест на ПЛИС (seed 1, программа 6, задержки 2/3) упал с той же сигнатурой, что `flushed_load_min`.
Команды: `tools/measure.sh` (шаг cva6) — `run.sh --model-opt program=repro/<тест> --model-opt lat=0,0
--batch 1048576 --squash 1`.

| тест | что проверяет | результат (cv32a60x, ext/cva6 81245a4) |
|---|---|---|
| `flushed_load_min.bin` | найдено генератором (seed 10, программа 3; seed 12 — та же сигнатура), сжато `tools/minimize_prog.py` до 8 значимых команд: `uret` (ловушка), невыровненная `lhu` (ловушка, cause 4), за ней две `lb`; обработчик генератора (4 `sw`, `csrr mcause/mepc`, `lhu` по `mepc`) | `lhu` в обработчике возвращает 0 вместо младшей половины команды (0xd083) → обработчик шагает на 2, возврат в середину команды, дальше ловушки по кругу. Не зависит от задержек памяти обёртки (`lat` 0..4). Похожей задачи в трекере не найдено (#3553 — другой сценарий, std_nbdcache). **Не подтверждено**, что это ядро, а не обёртка: нужен разбор по временной диаграмме. Короткий направленный тест (`flushed_load.S`) сбой пока не повторяет. На эталоне с ассертами RTL (`OCV_PC_ASSERT=1`) падает ассерт hpdcache `ctrl: bad SIZE for request` (такт 277131) |
| `stale_load_min.bin` | найдено генератором (seed 5, программа 6; ещё 9 из 22 seed на программах 5–8), сжато до 11 слов: запись в `mimpid` (ловушка), `lb`, невыровненная `lw` (ловушка), `lw`, `sb`, `c.unimp` (ловушка; обработчик читает `lhu` по `mepc` слово `0x00010000`), затем `lh a6, -1094(t6)` по адресу вне памяти (0xFFFFFBBA) | ядро возвращает в `a6` 1 вместо 0 — верхнюю половину слова, прочитанного обработчиком. `stale_load_min_v5.bin` (та же программа, в слове `0x00050000`): ядро возвращает 5 — данные **чужой** загрузки. Обвязка отдаёт 0 (`ocv_axi_mem`: буфер чистится на каждый AR, вне памяти 0, OKAY). Ассерт hpdcache `ctrl: bad SIZE for request` (такт 273513) — ядро подаёт в свой кэш запрос недопустимого размера; на проходящих программах ассерт молчит. Зависит от задержек памяти: `lat=0,0` и `2,3` — сбой, `4,4` — проходит. Вероятно, та же причина, что у `flushed_load_min.bin`. **Кандидат, не отправлено** |
| `mie_disable.S` | прерывание после записи в `mie`: включение — ловушка сразу; выключение — больше ни одного прерывания (привилегированная спецификация 3.1.9) | ловушка после включения на 1 команду позже в 15 из 16 раундов; прерывание **после** `csrw mie, x0` в 7 из 8 раундов. Известная ошибка [openhwfoundation/cva6#3175](https://github.com/openhwfoundation/cva6/issues/3175): запись `mie` не сбрасывает конвейер, а прерывание привязывается к команде на декодировании |

```bash
examples/cva6/repro/run.sh mie_disable          # ядро в Verilator на ПК + модель; линия таймера (mip 7) держится высокой
```

Тест считает сам (регистры в конце, они же в памяти по `0x8100`): `s0` — взято прерываний (24), `s1` — взято при
выключенном MTIE (должно быть 0), `s4` — взято не сразу после включения (должно быть 0). Модель OCV на том же прогоне
отмечает каждое прерывание, которое её состояние не разрешает (`cause + 0x100` в потоке irq).

```bash
OCV_PC_ERRORS=5 build/baseline/cva6/pc/obj/tb_pc --model-opt program=examples/cva6/repro/flushed_load_min.bin   # (после hw/cpu/run.sh cva6.bind pc)
OCV_PC_ASSERT=1 OUT=build/assert/cva6 hw/cpu/run.sh examples/cva6/cva6.bind pc examples/cva6/repro/stale_load_min.bin   # с ассертами RTL
```
