# SCR1 как DUT платформы OCV

Процессорное ядро SCR1 (RV32IMC) подключено к OCV тем же способом, что и любое IP-ядро:
описанием [scr1.json](scr1.json) и моделью [scr1_model.c](scr1_model.c). Платформу ради
процессора не меняли.

- **Стимул — программа.** Канал `program` (source) загружает образ 64 КиБ ОЗУ по одному слову
  на запись; запись с `last` запускает ядро с вектора сброса 0x200.
- **Выход — исполненные инструкции.** Канал `retire` (monitor, RVFI-lite: `pc`, `pc_next`,
  `rd_addr`, `rd_wdata`, `trap`) — одна запись на инструкцию. Он `lossless`: пока его буфер
  (4096 записей) полон, такт ядра остановлен, прогонщик сливает буфер в память PS, и ядро
  продолжает. Длина прогона буфером не ограничена.
- **Конец программы** — переход на `SIM_EXIT` (0xF8), соглашение тестов SCR1: после этой
  инструкции адаптер держит ядро в сбросе.
- **Модель** — ISS RV32IMC (`models/cpu/iss/rv32_iss.c`, та же, что сверена с ядром в
  симуляции и на кристалле) с картой памяти адаптера. Значения, которые ISA оставляет
  реализации (CSR счётчиков тактов, чтения таймера), модель берёт у DUT через `observed()`, так
  что самоизмеряющие программы идут с ядром в ногу и сравниваются точно.

## Состав

| Файл | Что |
|---|---|
| `scr1_ocv_dut.sv` | адаптер: SCR1 + ОЗУ 64 КиБ на его AXI + загрузчик программы + поток RVFI + остановка на `SIM_EXIT` |
| `scr1_ocv_axi_mem.sv` | AXI4-слейв к порту ОЗУ (INCR/FIXED, WSTRB, неотображённые адреса: запись игнорируется, чтение 0) |
| `scr1.json` | описание DUT для генератора |
| `scr1_model.c` | модель: ISS + карта памяти + стимулы из образа программы |
| `run_cosim.sh` | косимуляция: `run_cosim.sh <program.hex>` |
| `gen_random_prog.py` | генератор случайных программ RV32IM (граничные значения, АЛУ, сдвиги, умножение/деление, переходы, загрузки/сохранения, цикл) |
| `faults.sh` | кампания внесённых неисправностей в RTL SCR1 (копия `scr1/src`, исходники не меняются) |
| `programs/` | образы `hello` и `dhrystone21` (собираются `scr1/sim/rvfi_coverif/co_verify.sh`) |

Ядру нужны `SCR1_RVFI_EN` (сырой поток RVFI из `scr1_top_axi`) и конфигурация
`SCR1_CFG_RV32IMC_MAX`; `run_cosim.sh` задаёт их сам.

## Запуск

```bash
examples/scr1/run_cosim.sh examples/scr1/programs/hello.hex
examples/scr1/gen_random_prog.py --seed 7 -o /tmp/r7.hex && examples/scr1/run_cosim.sh /tmp/r7.hex
examples/scr1/faults.sh /tmp/r7.hex
```

## Результаты (косимуляция)

| Программа | Инструкций сверено | Сливов буфера | Итог |
|---|---|---|---|
| `hello` | 9 610 | 2 | PASS |
| `dhrystone21` (самоизмеряющий) | 164 891 | 40 | PASS |
| случайная, seed 1 (4000 операций × 10) | 35 936 | 8 | PASS |

Кампания неисправностей в RTL ядра:

| Неисправность | `hello` | `dhrystone21` | случайная программа |
|---|---|---|---|
| `sra` работает как логический сдвиг | пропущена | пропущена | найдена (инструкция 155) |
| сдвиг влево на 1 не выполняется | пропущена | пропущена | найдена (319) |
| `bge` игнорирует переполнение | пропущена | пропущена | найдена (3712) |
| `bgeu` неверен при `op2 = 0xFFFFFFFF` | — | — | найдена (2129) |
| `mulhu` считается как `mulhsu` | пропущена | пропущена | найдена (1737) |

`hello` не исполняет ни сдвигов, ни умножений; в dhrystone `srai` идёт только по
неотрицательным числам, сдвига на 1 и переполнений сравнения нет. Платформа находит ошибку,
когда стимул её задевает; случайные программы с граничными значениями закрывают то, что
бенчмарки пропускают. Каждая находка — с точным местом: номер инструкции, `pc`, поле,
значения DUT и модели, предыдущие инструкции.

## Эталонная модель процессора: подключаемая (`iss` или Spike)

Модель SCR1 обращается к процессору через единый интерфейс
[`models/cpu/cpu_model.h`](../../models/cpu/cpu_model.h): шаг = одна инструкция в виде записи
RVFI, память — области адаптера плюс MMIO-обработчики, значения из DUT подставляются
обработчиками. Реализация выбирается при запуске: `--model-opt cpu=iss|spike`. Новая модель —
это один файл с `cpu_impl_t` и строка в реестре `cpu_model.c`; модель DUT и платформа не меняются.

| Реализация | Что умеет | Когда |
|---|---|---|
| `iss` (встроенная, `rv32_iss.c`) | RV32IMC без исключений и CSR машинного режима | быстрые прогоны программ, без внешних зависимостей |
| `spike` (riscv-isa-sim, официальная эталонная модель RISC-V) | весь ISA: исключения, CSR, `mret`, привилегии | полная проверка, набор `riscv_isa` |

Значения, которые ISA оставляет реализации, задаёт адаптер DUT, а не модель:
- счётчики тактов и таймер — из того, что прочитало ядро (`timing_csr`, `observed()`);
- аппаратно заданные CSR (`misa` только для чтения, `mvendorid`, `marchid`, `mimpid`) — списком
  `fixed_csrs` из `scr1_csr.svh`.

Spike собирается один раз скриптом `tools/get_spike.sh` (зафиксированная ревизия) и
подключается через `source models/cpu/spike.env`.

```bash
tools/get_spike.sh
(source models/cpu/spike.env; export CPU_SRCS CPU_CFLAGS MODEL_CXXFLAGS MODEL_LIBS
 examples/scr1/run_cosim.sh examples/scr1/programs/dhrystone21.hex -- --model-opt cpu=spike)
examples/scr1/run_isa.sh spike          # набор riscv_isa, 56 тестов
```

Набор `riscv_isa` (rv32ui/um/uc/mi, сборка SCR1), каждая инструкция сверяется с моделью,
включая исключения, обработчики и CSR:

| Модель | Прошло | Почему |
|---|---|---|
| `spike` | **56 из 56** | — |
| `iss` | 0 из 56 | окружение тестов уже на старте использует `mret` и CSR машинного режима |

Прогон набора занимает 32 с: Verilator и модель собираются один раз (`COSIM_PREBUILT`); при сборке
для каждого теста было бы 17 мин.

Найдено при подключении Spike: отвод RVFI в SCR1 выдавал в `pc_next` для `mret` и исключений
адрес, следующий за инструкцией, а не архитектурный (`mepc` или вектор ловушки). Лёгкая модель
этого не видела, потому что не моделирует ловушек. Отвод исправлен (`scr1_pipe_top.sv`).

## Генерация программ по покрытию (обратная связь на PS)

`--model-opt gen=random|directed` — программы не из файла, а генерируются моделью на процессоре во
время прогона, по одной на пачку (`--batches N --reset-each-batch`). Покрытие (`scr1_cov.c`, 1478 бинов:
операция × класс каждого операнда — 0, 1, −1, INT_MIN, INT_MAX, прочие положительные и отрицательные)
собирается по каждой выполненной и сверенной инструкции; в режиме `directed` каждая следующая
программа (`scr1_gen.c`) нацелена на бины, которые предыдущие не задели.

```bash
examples/scr1/run_cosim.sh gen:directed -- --batches 6 --reset-each-batch
examples/scr1/cov_faults.sh 6          # случайная против направленной на внесённых ошибках
```

Покрытие за 6 программ (около 215–245 тыс. инструкций): случайная — **68.8%** и выходит на плато;
направленная — **100%** уже к 4-й программе.

Угловые ошибки (неверный результат только при одном сочетании операндов), 6 зёрен генератора,
бюджет 6 программ:

| Ошибка | Случайная | Направленная |
|---|---|---|
| `sltu` неверен для (INT_MAX, INT_MIN) | не найдена ни разу (0 из 6) | найдена 6 из 6, медиана ~50 тыс. инструкций |
| `div` неверен для INT_MIN / −1 | 6 из 6, медиана ~93 тыс. | 6 из 6, медиана ~50 тыс. |
| `rem` неверен для отрицательного делимого и делителя 1 (зерно 1) | 2 814 | 1 744 |
| `mulh` неверен для INT_MIN × INT_MIN (зерно 1) | 176 | 3 098 |

Частые случаи случайная генерация находит не хуже (её регистры стартуют с граничных значений);
выигрыш направленной — в редких сочетаниях, которые случайная задевает только по везению.

Граница модели: ловушки (`ecall`, исключения) и CSR машинного режима ISS не моделирует,
поэтому набор `riscv_isa` (заканчивается через `ecall`) пока не поддерживается.
