# UVM-тесты на плате: все пути, сценарии и результаты

Сводка всего, что проверялось по переносу UVM-тестов верификатора на гибридную систему: тестбенч —
на ARM (Cortex-A72, 550 МГц, частоту не поднимаем), проверяемое ядро — в ПЛИС той же платы (VD100).
Даты — 2026 год. Все прогоны, кроме отмеченных, — **0 ошибок**.

## 1. Правила, в которых работали

- **Тест верификатора не правится руками.** Всё, что меняется, делают скрипты при сборке: подмены
  через фабрику UVM из сгенерированной вершины платы, копия файла скриптом, обёртка вокруг ядра — наша
  работа. RTL ядра не меняется и не пересобирается под тест.
- **Главная цель для UVM — бесшовный перенос на ПЛИС**; ускорение допускает обоснованные допущения
  (SVA, потактовое покрытие и т.п.) — каждое перечисляется с причиной.
- **Покрытие — полное**, но не обязательно потактовое: потактовые covergroup можно снимать по изменению.
- **Главный способ сверки — эталонная модель на C через DPI** (из scoreboard); эталон на SV в scoreboard
  — запасной путь. **От UVM не отказываемся**: перенос UVM-тестов обязателен.
- **Время в тестбенче — только такты ядра** (никаких `#1` для опроса); основной режим — «плата».

## 2. Пути (варианты) — что пробовали

| путь | как устроен | статус |
|---|---|---|
| **A. UVM на ПК** — эталон для сравнения | тестбенч + RTL в одной модели Verilator (`build_board.sh pc`), для справки xsim | основа всех сравнений |
| **B. «Как есть» на плате** | тестбенч целиком собран Verilator'ом для ARM, ядро в ПЛИС; каждая транзакция агента идёт через ARM (`+OCV_ASIS`) | работает, выигрыш ×1.2–1.4 |
| **C. Переведённый (`uvm2board.py`)** | скрипт читает тестбенч и пишет «надстройку»: scoreboard → движок A (окна записей сворачиваются в ПЛИС в подписи CRC, модель на ARM сворачивает свои, при расхождении — повтор окном 1), последовательности → блоки транзакций; описание DUT берётся из SV-интерфейса и драйвера/монитора (`tbparse.py`, без json) | работает, основной результат: ×11–76 |
| **D. Без модели (scoreboard на SV)** | тот же перенос для IP без эталона на C: блоки, повторное использование объектов транзакций, кэш планов решателя ограничений | работает: ×5 (SHA-256), ×0.5 (mac16) |
| **E1. | **E2. Чужой тестбенч, вариант 2 — ускоренный (тест 1, `examples/cv32e40p/uvm_fast`)** | тестбенч core-v-verif на ARM, ядро работает в ПЛИС само; до тестбенча доходят только обращения к виртуальной периферии (через его OBI-агента); такт тестбенча стоит, время догоняет такты ядра; каждая команда сверяется с моделью OCV | на ПК: ×33–143; плата — следующий шаг |
| **F. Отклонено** | UVM на ПК + ARM как транспорт (классическая коэмуляция — много готовых решений); второе ядро A72 под стимулы; повышение частоты ARM; пакетный интерфейс модели (замерен: выигрыша нет) | не делаем |

## 3. Результаты

### 3.1. SCR1, тест с эталонной моделью через DPI (пути A, B, C)

Программы: r1 — случайная (36 тыс. команд), r2 — случайная (362 тыс.), r3 — случайная (3.68 млн),
dhrystone. ПК — тестбенч в стиле верификатора (`examples/scr1/uvm_v`) в Verilator.

| дата | вариант | r1 | r2 | r3 | dhrystone |
|---|---|---:|---:|---:|---:|
| | **ПК, Verilator** | 1.08 с | 8.85 с | 84.3 с | — |
| 10-06 | плата, «как есть» | 3.57 с | 12.3 с | 105 с | — |
| 10-06 | плата, переведённый, окно 1 (без свёртки) | 0.241 с | 0.836 с | 7.09 с | — |
| 10-06 | плата, переведённый, окно 4096 | 0.160 с | 0.372 с | 2.53 с | — |
| 10-07 | то же, тестбенч без json (`uvm_v`) | 0.175 с (×6.2) | 0.396 с (×22) | 2.65 с (×32) | — |
| 10-08 | + загрузка всей памяти, блок останова | 0.205 с | 0.434 с | 2.75 с | 0.247 с |
| 10-10 | + сверка записей в память и CSR (запись 219 бит) | 0.223 с | 0.608 с | 4.54 с | 0.331 с |
| 10-10 | **+ модель JIT RV32→AArch64 и LTO** | — | — | **1.10 с (×76)** | 0 ошибок |

Рост скорости эталонной модели на плате (r3, окно 4096): ISS 4.54 с → интерпретатор с предекодированием
2.62 → «fast» 1.95 → JIT 1.70 → JIT + LTO **1.10 с**. Остаток профиля: свёртка окна и CRC 32%, раздача
записей 19%, `board_ref` 15%, сам JIT-код 10%.

Где время на плате до JIT (r3, 2.39 с проверки = 650 нс/команду): ISS верификатора ~57%, платформа ~43%;
A72 на 550 МГц: ISS 274–345 нс/команду против 26 нс на ПК; ПЛИС — 47 нс/команду.

### 3.2. Без модели, scoreboard на SV (путь D)

| тест | ПК, Verilator | плата, «как есть» | плата, ускоренный | выигрыш |
|---|---:|---:|---:|---:|
| SHA-256, 10 тыс. блоков (~65 тактов на блок) | 3.37 с | 3.30 с | 0.744 с | ×4.5 |
| SHA-256, 100 тыс. блоков | 33.6 с | 31.5 с | 6.57 с | ×5.1 |
| mac16, 20 тыс. транзакций (1 такт на транзакцию) | 0.85 с | — | 1.67 с | ×0.5 |
| mac16, 200 тыс. | 7.69 с | 77.8 с | 16.05 с | ×0.48 |

mac16 — граница метода: 12.7 из 16 с уходит на `randomize()` на ARM (~60 мкс на вызов — подготовка
вызова в коде Verilator, не наш решатель). Плата выигрывает, когда на транзакцию приходятся десятки тактов
ядра. На ПК для mac16: блоки + повторное использование объектов ×2.2, кэш планов решателя — ещё ×1.35
(форма платы на ПК: 1.05 → 0.48 → 0.355 с против 0.854 с обычной симуляции).

Тестбенч core-v-verif собран Verilator'ом без правки его файлов (4 исправления в Verilator, компонент

| программа | команд | ПК, обычная симуляция | вариант 1, плата (синхронно) | вариант 2 = тест 1, ПК (ПЛИС в Verilator) |
|---|---:|---:|---:|---:|
| hello-world | 13 тыс. | 8.9–12 с | 72 с (такт в такт с ПК) | 0.9 с |
| dhrystone | 157 тыс. | 104–129 с | 872 с (такт в такт с ПК) | 3.2 с (×33–40) |
| coremark | 2.79 млн | 1856–2257 с | ~4 ч (не запускался) | 15.8 с (×118–143) |

Вариант 1 доказывает бесшовность: тестбенч без подмен, все ассерты и покрытие на значениях ядра в ПЛИС,

тестбенча (агенты OBI ~35%, обмен ~29%, виртуальная периферия ~6%, покрытие отладки 2.2%).

- Время включает запуск процесса. До 13.10 `run.sh` копировал программу тестбенча (40 МБ) в `/tmp` на

**Третий проход, 13.10 вечером, после улучшений** (без правок тестбенчей): профиль mac16 на плате показал
75% времени в `randomize() with {...}` — из них `VlRandomizer::hard` 29% (строка «файл:строка + исходник»
собиралась на каждом вызове), наш решатель 21% (побайтовый хэш ~1.5 КБ текста ограничений), `sformat` 11%.
Сделано: место ограничения хранится указателями на литералы и форматируется только для сообщения

вместо `-Os` (`uvm/build_board.sh`); хэш решателя — по 8 байт; `run.sh` без копирования программы.

### 3.4. Стоимость частей UVM на ПК (замеры для планирования)

| что | цена |
|---|---|
| монитор: объект + `ap.write` | 2.2 мкс на запись |
| sequence → sequencer → driver | ~30 мкс на транзакцию |
| блок транзакций (K=256) | 0.13 мкс на запись (×17 дешевле) |
| SCR1 в Verilator, 1 копия | 1.07 МГц = 3.48 мкс на команду |
| xsim без UVM / с UVM | ~150 / 190 мкс на команду |
| Verilator UVM, путь платы на ПК | 8.8 мкс на команду |
| модели на ПК: ISS / Spike / QEMU TCG | 26 / 50 / 0.55 нс на команду |

Свёртка окон (движок A): случайная программа, окно 256 — данных в 32 раза меньше, 4096 — в 496 раз;
dhrystone, 4096 — в 696 раз.

## 4. Найденные ошибки

- **Внесённые в ядро:** SCR1 — 5 ошибок АЛУ/загрузок/ветвлений найдены и как есть, и в переведённом тесте
  (переведённый: окно 4096 → повтор окном 1 → та же первая неверная команда за 0.8 с против 2.6 с);
  CV32E40P — 7 из 7 (сгенерированный тест без UVM, `examples/cv32e40p/gen/faults.sh`).
- **Платформы — найдены на плате:** окно хаба было фиксированным 1 МБ (SHA нужно 4 МБ → размер из
  метаданных); тестбенч грузил память только до последнего ненулевого слова (dhrystone читал данные прошлой
  программы); прогон «как есть» с >10 тыс. транзакций при замороженном ядре — Verilator `DIDNOTCONVERGE`.
- **Тестбенча:** dhrystone в тестбенче SCR1 падает и на ПК — модель не получала значений таймера
  (исправлено каналом значений CSR от ядра).

## 5. Допущения ускоренных вариантов

| что не выполняется | где | почему допустимо |
|---|---|---|
| SVA-ассерты на сигналах внутри ядра (51 у CV32E40P) | E2 | ядро в ПЛИС; их работу делает сверка каждой команды с моделью; в варианте 1 они выполняются |
| пошаговая сверка с ISS Imperas | E2 | коммерческий ISS недоступен; вместо него — модель OCV |
| потактовое покрытие отладки | E2 | отладку тесты не используют; по направлению — снимать по изменению |
| точная последовательность задержек памяти | C, E2 | задержки — по тем же настройкам теста, но генерирует ПЛИС |
| `dist`-веса ограничений | все на Verilator | Verilator 5.052 их не учитывает (и на ПК тоже) |
