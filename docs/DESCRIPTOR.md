# Описание DUT (дескриптор) — справочник

Чтобы подключить IP-ядро к OCV, достаточно двух вещей: **описания** (JSON) и **эталонной
модели** (C). По описанию `gen/ocv_gen.py` генерирует обёртку для ПЛИС и метаданные для
программы на PS; ни ядро платформы, ни платформенный слой при этом не меняются.

```bash
gen/ocv_gen.py my_ip.json -o build/gen
#   my_ip_ocv.sv          обёртка: DUT + хаб + конечная точка на каждый канал
#   my_ip_ocv_meta.h      таблицы для программы на PS
#   my_ip_ocv_meta.json   то же для скриптов
```

Пример целиком — [examples/mac16/mac16.json](../examples/mac16/mac16.json).

## Верхний уровень

| Ключ | Обязательный | Смысл |
|---|---|---|
| `name` | да | имя окружения; обёртка называется `<name>_ocv` |
| `module` | да | имя модуля DUT |
| `clock` | да | тактовый порт DUT (подключается к такту платформы) |
| `reset` | нет | `{"port": "rst_n", "active": "low"\|"high"}` — сброс DUT; им управляет хаб (регистр `DUT_CTRL`) и сброс платформы |
| `parameters` | нет | параметры модуля DUT: `{"WIDTH": 16}`; значение — число или выражение SV |
| `tie` | нет | входы DUT, подключаемые к константам: `{"mode": "2'b01"}` |
| `export` | нет | порты DUT, выводимые из обёртки наружу: `[{"port": "irq", "dir": "out", "width": 1}]` |
| `channels` | да | список каналов, от 1 до 254 |
| `description` | нет | комментарий |

Каждый порт DUT может быть упомянут только один раз; генератор это проверяет.

## Каналы

Канал — поток транзакций через один интерфейс DUT. Каждый канал получает свою конечную
точку и свой слот в адресном пространстве хаба (по порядку в списке, начиная с 1).

| Вид (`kind`) | Направление | Порты | Конечная точка |
|---|---|---|---|
| `source` | стимулы → вход DUT | `valid` — вход DUT; `ready` — выход DUT (если нет — DUT принимает каждую запись) | `ocv_source` |
| `sink` | выход DUT → буфер | `valid` — выход DUT; `ready` — вход DUT (если задан, платформа — потребитель потока с backpressure, без потерь) | `ocv_sink` |
| `monitor` | наблюдение | `valid` — строб завершённой транзакции; платформа ничем DUT не управляет | `ocv_sink` без backpressure |

| Ключ | Смысл |
|---|---|
| `name`, `kind`, `valid`, `fields` | обязательные |
| `ready` | порт готовности (для `source` и `sink`) |
| `depth` | глубина буфера в записях, степень двойки от 2 до 2^24 (по умолчанию 1024) |
| `lossless` | только `monitor`: `true` — пока буфер полон, DUT **заморожен** (генератор ставит вентиль на его такт), прогонщик сливает буфер и отпускает DUT. Поток любой длины без потерь и без изменений в DUT |
| `stall` | только `monitor`, вместо `lossless`: вход DUT «пауза» (активный 1), если в самом DUT есть такой вход |
| `stream` | только `source`: реактивный канал. Буфер — кольцо, которое во время прогона пополняет модель (`react()` → `io->send()`), отвечая на то, что DUT только что выдал: данные на запрос чтения, ответ протокола. Стимулов от `stimulus()` не получает |
| `freeze_when_starved` | только `source`, нужен `ready`: пока DUT готов принять запись (`ready`), а записи нет, его такт стоит. DUT не видит, сколько модель думала над ответом. `ready` должен означать «жду данные» — DUT, который держит `ready` всегда, замёрз бы навсегда |
| `squash` | только выходы без потерь (`monitor` с `lossless` или `sink` с `ready`), поля только `exact`/`ignore`: конечная точка умеет **сливать окна** записей. Вместо каждой записи она хранит одну на окно из N: последнюю запись, число записей и две подписи CRC32C и CRC32 по сравниваемым битам всех записей окна. N задаётся при прогоне (`--squash N`, по умолчанию 1 — каждая запись, как без ключа). Прогонщик сливает записи модели так же и сравнивает подписи; расхождение окна автоматически уточняется повторным прогоном с `--squash 1` |

## Поля

Запись канала — это поля, упакованные подряд начиная с младшего бита в порядке списка и
выровненные до 32-битных слов.

| Ключ | Смысл |
|---|---|
| `name` | имя поля; по нему модель читает и пишет значения (`ocv_get`, `ocv_set`) |
| `port` | порт DUT |
| `width` | 1..64 бит |
| `signed` | знаковое (для печати, правила `abs` и `ocv_get`) |
| `compare` | только для `sink`/`monitor`: правило сравнения с моделью |

### Правила сравнения

| Правило | Когда нужно |
|---|---|
| `"exact"` (по умолчанию) | побитовое совпадение |
| `"ignore"` | недетерминированные поля: метки времени, счётчики тактов, значения, зависящие от задержек |
| `{"mask": "0xFF00"}` | сравниваются только биты маски (часть поля не определена спецификацией) |
| `{"abs": N}` | целые значения, отличающиеся не более чем на N (с учётом `signed`) |
| `{"ulp": N, "fp": "fp16"\|"fp32"\|"fp64"}` | числа IEEE-754 в пределах N единиц младшего разряда; NaN равен любому NaN, +0 равен −0; ширина поля должна совпадать с форматом |

## Идентичность

`DUT_ID` — CRC32 канонического текста описания. Он записывается в хаб при генерации и в
метаданные для PS. Программа на PS отказывается работать, если `DUT_ID` хаба не совпадает с
её метаданными, — так прошивка и программа от разных версий описания не смешиваются.

## Что генератор проверяет

Неизвестные ключи, `lossless` не у монитора или вместе со `stall`, `stream`/`freeze_when_starved` не у источника, `freeze_when_starved` без `ready`, `squash` у источника, у монитора, который может терять записи, или у поля с допуском (`mask`/`abs`/`ulp`), имена-идентификаторы, повторные имена каналов и полей, повторное
использование порта DUT, глубину (степень двойки), ширину поля, согласованность правила
сравнения с полем (маска в пределах ширины, ширина под формат IEEE-754), правила сравнения
у стимулов (запрещены), `ready` у монитора (запрещён), `stall` не у монитора (запрещён).
Сообщение указывает путь к ошибке, например `channels[1].fields[0]: fp32 needs width 32`.
