# Плата ALINX VD100: что нужно знать

## Плата

- Кристалл AMD Versal AI Edge **XCVE2302**: 2× Cortex-A72 (PS, Linux), ПЛИС — 150 тыс. LUT, 155 блоков
  RAMB36, 155 URAM, 464 DSP. Плата: 4 ГБ DDR4, консоль USB-UART, SD-карта.
- Linux (PetaLinux с карты ALINX) загружается сам и входит под root.
- Хаб OCV в ПЛИС виден процессору по адресу **0x80000000** (`/dev/mem`), окно — по описанию ядра (8 МБ для ядер).

## Файлы — только через SD-карту

Консоль — только для команд; файлы на плату попадают через раздел FAT карты.

| файл на карте | откуда |
|---|---|
| `BOOT.BIN` | образ ПЛИС + прошивка A72: `platforms/vd100/build.sh` (собирает сам из `sd/BOOT_ref.BIN`) |
| `image.ub`, `boot.scr` | Linux: `platforms/vd100/sd/` (с карты ALINX) |
| `BOOT_<ядро>.BIN`, `ocv/cpu/<ядро>/`, `ocv/cpu/use.sh` | несколько ядер на одной карте: `hw/cpu/make_sd.sh` |

`platforms/vd100/sd/BOOT_ref.BIN` — заводской BOOT.BIN ALINX: из него берётся прошивка A72 (bl31,
u-boot), к ней добавляется наш образ ПЛИС (`tools/make_bootbin.sh`).

## На плате

```sh
F=/run/media/FAT-mmcblk1p1                  # раздел FAT карты (или: mount /dev/mmcblk1p1 /mnt)
sh $F/ocv/cpu/use.sh cva6 && reboot         # какое ядро загрузится (образ ПЛИС)
sh $F/ocv/cpu/cva6/board_run.sh             # сгенерированный тест + программы
$F/ocv/cpu/cva6/run.sh --info               # проверка моста и хаба, ничего не запуская
```

С ПК команды можно давать через консоль: `platforms/vd100/tools/console.py '<команда>'`
(/dev/ttyUSB0, 115200; печатает вывод и возвращает код завершения команды).
Порядок дня с платой — `docs/BOARD_DAY.md`.

## Сборка образа ПЛИС (Vivado 2023.2)

```bash
export VIVADO_SETTINGS=<Vivado>/2023.2/settings64.sh
LC_ALL=C hw/cpu/run.sh examples/cva6/cva6.bind vd100     # ~20–40 мин
```

| ядро | частота | запас по времени | логика ядра |
|---|---|---|---|
| CV32E40P | 50 МГц | +5.18 нс | 7.2 тыс. LUT, 3.7 тыс. FF |
| SCR1 | 50 МГц | +3.32 нс | 13.3 тыс. LUT, 7.7 тыс. FF |
| CVA6 (cv32a60x) | 50 МГц | +8.15 нс | 10.5 тыс. LUT, 8.0 тыс. FF |

Подводные камни (все обходятся скриптами, здесь — чтобы знать почему):

- **Локаль**: Vivado в русской локали ломает разбор чисел — сборка идёт с `LC_ALL=C`.
- **Память ПК**: параллельные запуски Vivado (`OCV_JOBS`) на большом ядре съедают всю память — для CVA6
  `OCV_JOBS=2`; ПК уже перезагружался от перегрузки.
- **`srcscanner`** (служебный процесс Vivado 2023.2, порядок файлов) на CVA6 разрастается до 20+ ГБ: в имя
  каждого модуля вшита структура конфигурации в килобиты. Синтезу он не нужен — `build.sh` останавливает
  его, как только тот превысит 2 ГБ (`OCV_SRCSCANNER_GB`).
- **Блочной памяти не хватает** на ядро с большой RAM: большие буферы хаба кладутся в UltraRAM
  (`OCV_URAM_BITS`), RAM ядра — тоже (`memory ... uram` в привязке). UltraRAM выводится только при записи
  без одновременного чтения — так написан `hw/cpu/ocv_cpu_ram.sv`.
- **CVA6 на ПЛИС**: память кэшей — как в собственной FPGA-сборке CVA6 (`tc_sram_fpga_wrapper`,
  fpga-support), в конфигурации `TechnoCut=0` (ASIC-макросы памяти — пустые на ПЛИС); `FpgaEn` выключен —
  его регистровый файл не сбрасывается.
