# Функциональное покрытие в тестах по контракту (правило 7)

Состояние на 29.10.2026 (работа начата 27.10). Код: `mihasik258/uvm_board@5a46b2e` + незакоммиченные правки
(список ниже). Источники задачи: `docs/FOCUS.md` 4.1 «Осталось», 4.4 п.3; `docs/COVERAGE.md` 2.3–2.5.

## Решение (27.10)

- **Тест пишет обычный `uvm_subscriber #(<item>)` с covergroup** и подключает его к `ap` агента. В симуляции он
  получает каждую транзакцию, как обычно. Код теста один и тот же в обоих режимах.
- **На плате в канале, который сверяет `ocv_model_checker`, UVM-объектов на запись нет.** Поэтому монитор такого
  канала с подписчиками покрытия получает записи модели. В проходящем прогоне они совпадают с записями DUT: сверка
  подписями та же. Записи прореживаются в C до тех, что могут изменить покрытие (`uvm/ocv_uvm_tap.h`).
  - Запись проходит, если **проекция** на поля, которые читают подписчики, вместе с проекциями K предыдущих записей
    ещё не встречалась.
  - K предыдущих записей идут перед ней как **записи контекста**. Пока они проходят, covergroup выключены
    (`vl_covergroup_enable(0)`, тот же приём, что в обвязке COVERAGE 2.3). Поэтому состояние подписчика — последние
    K записей — такое же, как в полном потоке.
  - Бины совпадают точно; число попаданий в бин — нет. Отпечаток проекции 128-битный.
- **Что читают подписчики, выводит `uvm/ocv_contract.py` из исходника подписчика.** Это поля `<handle>.<field>`;
  постоянный срез `t.f[hi:lo]` даёт только эти биты. Если элемент передан целиком в функцию или вызван его метод,
  берутся все поля. Результат пишется в `ocv_cov_spec` производного пакета.
- **Состояние подписчика.**
  - Без своего состояния (только covergroup и item): K = 0.
  - Со своим состоянием подписчик объявляет `localparam int ocv_cov_history = K;` (изоковый: 3).
  - Состояние без объявления: на плате подписчик получает каждую запись. Это точно, но медленно; contract.py
    предупреждает.
- **Каналы-источники** (`ap` драйвера) идут на плате через UVM и так, там прореживать нечего. В тесте без
  covergroup ничего не меняется: монитор без подписчиков не подключается к выборке, и сборка остаётся прежней.
- **Почему так, а не фильтр COVERAGE 2.3.**
  - Фильтр 2.3 сделан под isacov: таблица генерируется из его исходников, записи RVFI идут в файл.
  - Здесь механизм общий для любого covergroup теста на транзакциях монитора, и выводится из теста автоматически.
  - Отбор по проекции с историей — тот же принцип, что в 2.3, уровень 2.

## Проверено (29.10, этот ноутбук)

**CVA6 cv32a60x, isacov на `issue`** (132 экземпляра covergroup):
- Подписчик переводит транзакцию `issue` в RVFI: слово команды, ECALL/EBREAK — с ловушкой.
- Значений rs1/rs2/rd в транзакции нет, поэтому их бины пусты в обоих режимах.

| программа | режим | сверка | покрытие | время |
|---|---|---|---|---:|
| minstret (200 045 команд) | симуляция ПК | 300 094 записи, 0 расхождений | среднее 3,35 % | 26,1 с (без покрытия 20,3 с) |
| minstret | форма платы на ПК | PASS, те же счётчики | отчёт **совпадает с ПК построчно** (все 132 экземпляра, каждый coverpoint/cross); 48 записей + 5 контекста из 200 045 | 3,59 с (без покрытия 3,41 с) |
| nettle-aes ×1 (4 074 031 команд) | симуляция ПК | 8 078 334 записи, 0 расхождений | среднее 18,96 % | 475 с |
| nettle-aes ×1 | форма платы на ПК | PASS | отчёт **совпадает с ПК построчно**; 1 213 + 54 контекста из 4 074 031 | 49,5 с (без покрытия 49,8 с) |

- **Число выбранных записей насыщается на длинной программе.** Это замер модели без DUT: стенд `bench_model` с
  выборкой; сам стенд в репозиторий не входит.
  - nettle-aes на 100 млн команд: 1 063 + 50 контекста.
  - Причина: у `issue` нет значений, проекция — слово команды, а длинный тест крутит один и тот же код.
- **Цена в модели (то, что важно на плате).**
  - Интерпретатор `fast` на ПК: 119–165 нс на команду против 128–156 без выборки, в пределах шума.
  - **jit (быстрый путь платы) под qemu-aarch64: 75 → ~365 нс на команду, примерно в 4,8 раза медленнее.**
  - Из этого ~250 нс — потеря свёртки блоков: fold и fuse выключаются для выбранного канала. Проверено:
    `OCV_NO_FOLD` + `OCV_NO_SQPUSH` без выборки дают 274 нс. Остальное — хеш на запись.
  - Подпись окон та же, сверка не меняется.
  - На A72 не мерено. Цифры qemu — только отношение.
- `t_tap.c`: проекции совпадают (3 483 из 3 483). Полный `uvm/test/run_tests.sh` после правок **не прогонялся**.

## Не проверено / осталось

- **OTBN, SCR1, cva6_64:** covergroup написаны, `ocv_contract.py` выводит для них проекции:
  - OTBN `rsp`: `rdata[1:0],rdata[31:28],err`, K = 0;
  - cva6_64 `issue`: `insn[11:0],insn[19:13]`.

  Но сборки (pc/host) и прогоны **не делались**: остановлено по лимиту времени 29.10. Нужно пересобрать
  `examples/{otbn,scr1,cva6_64}/uvm_c/run.sh pc|host` и сравнить отчёты `+ocv_cov_report` так же, как для CVA6.
- **Прежние тесты по контракту и mac16/SHA-256.** Пакет `ocv_uvm_pkg.sv` проверен линтом Verilator в обоих режимах.
  Правки обратно совместимы: без подписчиков с covergroup выборка не включается. Шаг 13 `test_all.sh` заново не
  прогонялся.
- **Сборка CVA6 стала тяжелее.**
  - Пакеты isacov и дизассемблер Spike; pc-сборка около часа при -j4–6, Verilator 1,6 ГБ.
  - Для aarch64 дизассемблер собирается кросс-компилятором через TB_C; `run.sh aarch64` **не собирался**.
- **Скорость jit с выборкой.** Чтобы вернуть скорость, выборка должна идти внутри jit (COVERAGE 2.5, уровень 1).
  - Для канала, где записи статичны по pc (как `issue`), — проверка «переход блок → блок (с историей K) уже был» на
    переход блока, а не на команду. Свёртка и fuse при этом сохраняются.
  - Это правка `models/cpu` (jit), вне этой задачи.
  - До неё: на плате либо покрытие с ~×4 по модели, либо `+OCV_NO_TAP` / `+NO_COV`. Во втором случае покрытие
    считается только в симуляции.
- **Для платы:**
  - `examples/cva6/uvm_c/run.sh aarch64` и `examples/otbn/uvm_c/run.sh aarch64`;
  - на плате прогнать nettle-aes ×1 и ×1100 с покрытием и с `+NO_COV`: замер цены на A72 и совпадение отчёта
    `+ocv_cov_report` с ПК.
