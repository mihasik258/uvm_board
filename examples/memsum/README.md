# memsum — реактивный DUT: модель отвечает на его запросы во время работы

`memsum` — маленькое ведущее устройство шины. Получает команду (адрес, длина), читает слова памяти
по одному запросу, после каждого ждёт ответ, накапливает контрольную сумму и выдаёт результат.
Памяти в ПЛИС нет: на каждый запрос отвечает эталонная модель на процессоре — сразу, пока ядро ждёт.

| Канал | Вид | Что |
|---|---|---|
| `cmd` | source | команды (адрес, длина 0..24) — обычные стимулы |
| `req` | sink с `ready` | запросы чтения ядра: модель видит каждый, как только он появился (`react()`) |
| `rsp` | source, `stream`, `freeze_when_starved` | ответы модели (`io->send()`); пока ответа нет, такт ядра стоит |
| `res` | sink с `ready` | результат: сумма, адрес, длина и `wait` — сколько своих тактов ядро ждало ответов |

`wait` сравнивается точно с длиной: при заморозке ядро ждёт ровно один свой такт на слово, как бы
долго процессор ни готовил ответ. Это встроенная проверка того, что время реакции скрыто от DUT.
С `--throttle-stream P` ответы приходят с опозданием (внесённая задержка памяти); тогда `wait` заранее
не известен, и модель берёт его у ядра (`--model-opt check_wait=0`, через `observed()`).

```bash
sim/cosim.sh examples/memsum/memsum.json examples/memsum/memsum_model.c \
                 examples/memsum/memsum.sv -- --batches 4
examples/memsum/faults.sh          # кампания неисправностей
platforms/vd100/build.sh examples/memsum/memsum.json examples/memsum/memsum_model.c \
                             examples/memsum/memsum.sv     # под плату
```

## Кампания неисправностей (косимуляция)

| Неисправность | Без задержек | С задержкой ответов / паузами |
|---|---|---|
| шаг адреса 8 вместо 4 | найдена (запрос 1) | |
| перенос адреса теряется на границе 4 КиБ (редкая) | найдена (запрос 197) | |
| сумма без поворота | найдена | |
| последнее слово не запрашивается | найдена | |
| счётчик ожидания не сбрасывается | найдена (поле `wait`) | |
| данные берутся без `valid` | **пропущена** | найдена с `--throttle-stream 128` |
| запрос уходит без `ready` | **пропущена** | найдена с `--throttle-out 128` (`DUT stalled`) |

Две последние — ошибки протокола, которые проявляются, только когда партнёр медлит. Ответ «без
задержки» делает проверку быстрой и точной, но такие ошибки прячет; поэтому у реактивных каналов
задержка вносится отдельно и управляемо.
