## 0. Правила владельца проекта (обязательны)

- **Цель — диплом.** Статья — только если результат того стоит.
- **Только сверхдлинные тесты.** Это тесты, которые на ПК идут десятки минут и часы (сотни миллионов
  команд), например тест A: Embench ×100 на CVA6.
  - Короткие тесты не оптимизировать и не использовать как замену длинным при замерах (даже `_s10`).
  - Короткие программы годятся только как быстрая проверка правильности.
- **Сценарий пользователя:** «мой тест на ПК, в X раз быстрее, без изменений». Ничего не делать под
  конкретный тест: DUT подключается к оболочке по `.bind`, тест переносится скриптом.
- **Плата штатная.**
  - Частоту A72 и настройки Linux не трогать.
  - Частота ПЛИС (`OCV_CLK_MHZ`) — тоже только с разрешения владельца.
- **Второе ядро A72 и копии DUT — нет.** Сначала техника, а не количество. Любой новый крупный шаг —
  сначала предложить и дождаться ответа.
- **Не выходить за пределы `/home/toast/verif-diplom`.** `~/pvo_scr1` не читать.
- **Память ноутбука.** Было два падения из-за нехватки памяти.
  - Всегда `ulimit -v`, перед долгими или параллельными прогонами следить за RSS.
  - Трассу CVA6 (`trace_hart_0.dasm`) направлять в `/dev/null`.
  - Vivado не запускать параллельно.
- **Git.**
  - Коммиты без строки `Co-Authored-By`.
  - `git push` делает владелец, агенту остаётся выдать команду.
  - Ошибки CVA6 в upstream не отправлять.
- **Пароли и учётные данные не вводить.**

3. **Совмещённый код jit** (`73c4d50`, `cpu_impl_t.fuse`). Код блока сам считает бины покрытия и
   сворачивает записи regw и store из регистров (`crc32cx`/`crc32x`):

### Шаг 2. Доводка горячего пути модели (без платы, проверка под qemu)

Инструмент — `tools/qprof.sh <программа.hex>`. Он печатает команды A72 на команду RISC-V (всего, код
jit, программа; по функциям и по строкам) и сначала сверяет подписи fast и jit. Сейчас на nettle-aes
это 67.7: код jit — 39.5, остальная программа — 28.2.

Уже сделано и проверено (18.10):

- **Состояние CRC окон в регистрах на весь блок** (x19–x22, `a2a7596`). nettle-aes 67.7 → 63.8, на
  коротких блоках нейтрально.
- **Пропуск покрытия у насыщенных команд проверен и отброшен.** И в коде jit, и в `cov_run` он
  медленнее: проверка стоит больше, чем экономит, потому что у команд с двумя операндами 49 бинов и
  насыщение почти не наступает. Не повторять.

Сейчас, в командах A72 на команду RISC-V: nettle-aes 63.8 (блок 39 команд), picojpeg 149.9 (блок 8),
huffbench 229.6 (блок 4). **Главная потеря — работа в C на каждый блок, а не код jit.** На huffbench
это ~190 из 230. Кандидаты по `qprof`:

- **(а) `fused_done`** — на каждый блок для каждого потока заново строится последняя запись окна
  (`cpu_stream_out` с полями из массива).
  - Последняя запись нужна только в конце программы: открытое окно закрывается слитой записью.
    Окно, которое заполняется внутри совмещённого блока, туда не попадает.
  - Можно копить её лениво: запомнить `cpu_bins_t` и выходы последней команды с записью, а собрать
    в конце программы. Если запись делает C-путь, он сам ставит `last`, и отложенное сбрасывается.
  - Обходить только совмещённые потоки (готовый список), а не все 8.
- **(б) `run_next`.** Копирование `x0` (128 байт) на каждый блок не нужно, когда блок берётся целиком
  через `jit_block` и совмещён. Флаг «нужны регистры до блока».
- **(в) `fold_block` + `emit_fold`.** Поиск в `fold_cache` по хэшу плюс вызов прогонщика по указателю
  на каждый блок.
  - Хранить указатель на свёртку в `binfo`.
  - Свёртку issue делать прямо в окне (`sq_[fold_s]`, `ocv_fold_apply`) без `io->emit_fold`.
  - Дальше можно перенести и её в код jit: CRC записей issue блока постоянен, сдвиг окна — PMULL.
- **(г) `block_info`.** Поиск по хэшу на каждый блок. Хранить указатель на `binfo` в самом блоке jit
  (поле в `jblock_t`, отдавать через `cpu_block_t`), с проверкой номера прогона.
- **(д) Обвязка цикла** в `run_program`: проверки прерываний, `next_idle`/`next_ask`, `block()` через
  указатель, разбор `dyn`. Смотреть по строкам после (а)–(г).
- **(е) Код jit** на длинных блоках (~35 команд): регистры RISC-V кэшировать в регистрах A72 внутри
  блока (меньше `ldr`/`str` в `f.x`).

**Критерий:** подписи и покрытие = fast на всех Embench s1 (см. §3), затем время теста A на плате.

### Шаг 3. Совмещение для других ядер (без платы)

- **CV32E40P.** У него три потока для совмещения (`regw nonload`, `regw load`, `store`), а jit
  поддерживает максимум 2 (`cpu_fuse_t.s[2]`, проверка в `jit_fuse`). Поднять до 4. Состояние окна
  и так читается из памяти, так что это только массивы и `OFF_FST`. Есть ещё поток `watch` (mie);
  проверить, что он не даёт записей внутри блока.
- **SCR1.** Один поток `retire` (pc, pc_next, insn, rd, wdata, trap) и своё покрытие `scr1_cov`.
  - Нужен вид записи RETIRE в `fz_record` (pc — константа, pc_next — константа или `x9`).
  - Нужен план покрытия для `scr1_cov`, как `cov_plan` в `cv32_cov`.
- **Проверка:** стенд модели для `examples/cv32e40p/cv32e40p.bind` и `examples/scr1/scr1.bind`
  (`hw/cpu/run.sh <bind> bench`) под qemu, подписи fast = jit. Длинные тесты для этих ядер — Embench
  ×100 (`tools/embench.sh 100 ...`).

  Сгенерированные программы: `--batches 200 --model-opt gen=directed`.
- **`t_fast`** (jit против iss по каждой команде, под qemu):

  ```bash
  uvm/test/run_tests.sh
  ```

  Блок про `jit model`.

## 4. Работа с платой

- **Плата:** ALINX VD100 (Versal), A72 на 479 МГц. Консоль — CP2102 `/dev/ttyUSB0`, 115200. Заводские
  файлы — `platforms/vd100/sd/README.md`.
- **Команда на плате:**

  ```bash
  python3 tools/board_con.py "<command>; echo X_$((2+2))" <timeout> "X_4"
  ```

  Консоль теряет символы на длинных строках. `IDLE=<s>` задаёт выход по тишине (по умолчанию 3 с):
  для долгих прогонов ставить большой.
- **Передать файл до ~1 МБ в сжатом виде:**

  ```bash
  gzip -9c f > f.gz && python3 tools/board_con.py --send f.gz /run/media/FAT-mmcblk1p1/ocv/...
  ```

  Передача идёт кусками с проверкой md5; сверить итоговый md5 с локальным. Больше — через перестановку
  SD-карты, попросить владельца.
- **Образы на карте:** `BOOT_<ядро>.BIN`.

  ```bash
  cp /run/media/FAT-mmcblk1p1/BOOT_cva6.BIN /run/media/FAT-mmcblk1p1/BOOT.BIN; sync; reboot
  ```

  Проверка образа:

  ```bash
  sh .../ocv/cpu/cva6/run.sh --info
  ```

  Должно быть `hub, endpoints and bus OK`.
- **Раскладка на карте:**
  - `ocv/cpu/cva6/{ocv_cva6,run.sh,embench/,repro/}`;
  - `ocv/bench/bench_cva6`;
  - сценарии `ocv/measure*.sh`;
  - результаты `ocv/results*/`.
  - Локальная копия набора — `build/board_set/sdcard/`.
- **Профиль на плате:** `OCV_PROF=/tmp/prof.txt sh run.sh ... --profile`. Свернуть стеки на плате
  через python3 и разобрать по `build/cpu/cva6/vd100/ocv_cva6.debug` (`tools/prof_report.py`). Для
  строк — та же программа с `OCV_PS_CFLAGS="... -g"`: машинный код совпадает, проверять по `.text`.
