# Верификация цифровых ядер на гибридной системе ПЛИС + ARM

Дипломная работа: функциональная проверка RISC-V ядер и IP-блоков **на кристалле**. Проверяемое ядро
работает в ПЛИС на настоящей частоте, тестбенч и эталонная модель — на ARM той же микросхемы
(AMD Versal, плата ALINX VD100). Каждая команда ядра сверяется с моделью; проверки, которые в симуляции
на ПК идут часами, на плате укладываются в минуты.

```
        ARM (Linux, A72)                                       ПЛИС
 ┌──────────────────────────────┐   AXI   ┌──────────────────────────────────────────────┐
 │ тестбенч UVM / генератор     │ ──────► │ хаб OCV: стимулы, захват записей, свёртка    │
 │ эталонная модель (C, JIT)    │ ◄────── │ окон в подписи (CRC), заморозка такта ядра   │
 │ сверка, покрытие             │         │ обёртка ядра: RAM, шины, устройства, потоки  │
 └──────────────────────────────┘         │ проверяемое ядро (RTL без изменений)         │
                                          └──────────────────────────────────────────────┘
```

## Результаты

**Плата VD100, 0 ошибок во всех прогонах** (ПК — тот же тест в Verilator):

| тест | проверка | ПК | плата | выигрыш |
|---|---|---:|---:|---:|
| SCR1, UVM-тест верификатора, 3.7 млн команд | модель через DPI, JIT RV32→AArch64 | 84 с | 1.10 с | ×76 |
| SCR1, тот же тест без переделки («как есть») | — | 147 с | 105 с | ×1.4 |
| SHA-256, 100 тыс. блоков | scoreboard на SV, без модели | 33.6 с | 6.6 с | ×5 |
| mac16, 200 тыс. транзакций | scoreboard на SV, такт на транзакцию | 7.7 с | 16.1 с | ×0.5 — граница метода |

**Тест 1 — чужой UVM-тестбенч (core-v-verif, CV32E40P)**, ядро в ПЛИС, каждая команда сверяется с
моделью; на ПК (ПЛИС смоделирована в Verilator), плата — следующий шаг:

| программа | команд | чистый UVM core-v-verif на ПК | тест 1 |
|---|---:|---:|---:|
| dhrystone | 157 тыс. | 104–129 с | 3.2 с |
| coremark | 2.79 млн | 1856–2257 с | 15.8 с |

**Тест 2 — полная проверка большого ядра без UVM (CVA6)**: генерация программ под покрытие (1695 бинов:
АЛУ, умножение/деление, ветвления, память, CSR, исключения, сжатые команды, невыровненные доступы,
прерывания), сверка каждой команды. Ко-симуляция: 99.9% покрытия за 4 программы, 0 ошибок; скорость
Verilator на ПК — 52 тыс. команд/с на ядро; образ ПЛИС собран (50 МГц), замер на плате — следующий шаг.

**Найденные ошибки:** все 7 внесённых ошибок CV32E40P (АЛУ, загрузки, ловушки, прерывания) находятся
сгенерированным тестом; ошибки в RTL SCR1 — так же; 2 ошибки платформы найдены на плате.

Все пути переноса UVM-тестов, сценарии и цифры: [docs/UVM.md](docs/UVM.md). План и допущения: [docs/ROADMAP.md](docs/ROADMAP.md).

## Как устроено

- **Хаб OCV** (`hw/rtl`): каналы стимулов и записей, сворачивание окон записей в подписи CRC (сверка без
  передачи каждой записи), заморозка такта ядра, пока процессор не готов, — результат не зависит от
  скорости ARM. [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)
- **Универсальная обёртка процессорного ядра** (`hw/cpu`, `gen/cpu_wrap.py`): ядро подключается файлом
  привязки `.bind` — имена портов, шины (OBI, AXI4 32/64), память, окна устройств, линии прерываний, что
  брать из ядра (RVFI или сигналы трассировщика). RTL ядра не меняется. [hw/cpu/README.md](hw/cpu/README.md)
- **Эталонные модели** (`models/cpu`): ISS, предекодирующий интерпретатор, JIT RV32IMC→AArch64; профили
  машинного режима CV32E40P и CVA6.
- **Перенос UVM-тестов на ARM** (`uvm`): тестбенч компилируется Verilator в программу для платы,
  агенты общаются с ПЛИС транзакциями. [uvm/README.md](uvm/README.md)
- **Плата** (`platforms/vd100`): блок-дизайн, сборка образа и SD-карты. [docs/BOARD.md](docs/BOARD.md)

## Быстрый старт

```bash
tools/get_verilator.sh                 # Verilator + UVM (один раз)
tools/get_cores.sh                     # проверяемые ядра и тестбенч core-v-verif в ext/ (фиксированные коммиты)

hw/cpu/run.sh examples/cva6/cva6.bind cosim gen:directed -- --batches 4 --reset-each-batch   # тест 2 на ПК
examples/cv32e40p/uvm_fast/run.sh host && \
examples/cv32e40p/uvm_fast/run.sh test +firmware=examples/cv32e40p/build/prog/dhrystone.hex   # тест 1 на ПК
test_all.sh                            # регрессия платформы

hw/cpu/run.sh examples/cva6/cva6.bind vd100    # образ ПЛИС + программа для платы (Vivado 2023.2)
```

День с платой — [docs/BOARD_DAY.md](docs/BOARD_DAY.md).

## Состав

| путь | что |
|---|---|
| `hw/rtl`, `hw/tb` | хаб OCV и его тесты |
| `hw/cpu` | универсальная обёртка процессорного ядра, запуск (cosim / ПК / плата), SD-карта |
| `gen` | генераторы: хаб по описанию, обёртка ядра по `.bind`, UVM-слой |
| `sw` | прогонщик, библиотека, программа для ARM |
| `models/cpu` | эталонные модели, генератор программ и покрытие |
| `uvm` | перенос UVM-тестбенчей на плату |
| `sim` | ко-симуляция в Verilator тем же C-кодом, что на плате |
| `platforms/vd100` | плата: блок-дизайн, сборка, файлы для SD (`sd/`) |
| `examples/cv32e40p` | CV32E40P: привязка, тест 1 (`uvm_fast`), внесённые ошибки |
| `examples/cva6` | CVA6: привязка и оболочка портов — тест 2 |
| `examples/scr1` | SCR1: описание, модель, генератор, UVM-тесты, внесённые ошибки |
| `examples/mac16`, `memsum`, `sha256` | непроцессорные IP: UVM без модели, реактивное ядро |
| `tools` | установка инструментов и ядер |
| `docs` | архитектура, план и результаты, плата |

Проверяемые ядра — сторонние проекты и в репозиторий не входят: `tools/get_cores.sh` берёт их в `ext/`.
